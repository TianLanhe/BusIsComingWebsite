# 监控 Dashboard 数据解释与技术监控增强设计

**日期**：2026-07-24

**后续规格短名**：`analytics-dashboard-observability`

**范围**：修复折线图重复 Tooltip 和自定日期不可用问题，并增强事件同期比较、稳定性与时延、
系统状态、流量指标、访客明细及侧栏信息架构。保持既有匿名采集范围、隐私边界、长期明细、
无备份、私有访问方式和“只保存明细、查询时即时统计”原则不变。

## 背景与已确认问题

当前 Dashboard 已能从匿名事件明细生成总览、流量、下载、事件、访客、性能和系统信息，但本轮
验收确认以下问题：

1. 时间序列图同时激活图表库的鼠标 Tooltip 和自定义键盘 Tooltip，导致一次悬停出现两个提示框。
2. 右上角选择“自定日期”不会执行任何动作；高级筛选内虽有两个日期输入框，但不会被自动打开。
3. 自定日期应用后，右上角没有显示实际起止日期，高级筛选中的草稿也可能与已应用范围脱节。
4. 事件明细四张摘要卡没有同期比较。
5. 性能页把 P50 和 P95 同时绘制在一张趋势图中，指标卡单位不明确，端点表也无法直观看出与上期
   的时延变化。
6. 原“失败与性能”、系统、访客和流量页的信息组织不足，部分实现与 Figma 原型不一致。

“事件明细共有 34 条，但流量趋势数值很少”已经通过私有查询复核为统计口径差异，而不是数据
丢失：当时 34 条由 4 次主页访问、21 次地点查询、8 次路线查询和 1 次下载组成；既有趋势只展示
主页 PV、主页 UV 和成功路线查询 UV。用户已确认本轮不改变该趋势图口径。

## 设计原则与采用方案

### 采用方案：扩展既有私有查询读模型

继续使用既有私有监控查询边界，一次查询同时返回当前周期与上一周期结果。前端只负责展示和
交互状态，不自行并发两次请求拼接比较结果。

采用该方案的原因：

- 当前周期和上一周期共享同一组筛选条件、时间边界与生成时刻，不会因两次请求产生偏移。
- 继续只从事件明细即时计算，不增加汇总表、缓存、队列或后台任务。
- 事件摘要、端点时延、SLI 和系统信息仍属于现有工作区，不需要新增私有端点。

未采用方案：

- **前端分别查询当前和上期**：请求数翻倍，刷新时刻可能不一致，边界规则会在多个页面重复。
- **新增多个专用报表端点**：会拆散现有工作区读模型，增加不必要的契约和错误处理表面积。
- **引入新的日期组件库**：当前只需要两个日期的顺序选择，浏览器原生选择器足够，新增依赖收益低。

## 日期范围交互

### 顺序选择

1. 用户在右上角日期控件选择“自定日期”。
2. 系统进入第 1/2 步并打开开始日期选择器。
3. 用户选择开始日期后，系统进入第 2/2 步并尝试打开结束日期选择器。
4. 若浏览器阻止自动打开第二个原生选择器，右上角控件保持“开始日期 – 选择结束日期”状态，用户
   再点击一次即可继续，流程不会失效。
5. 用户选择结束日期后立即校验并应用范围，只触发一次 Dashboard 刷新。

### 显示与同步

- 桌面端右上角显示完整起止日期，例如 `2026/07/01 – 2026/07/24`。
- 手机宽度不足时可显示 `07/01 – 07/24`，但无障碍名称保留完整年份。
- 展开高级筛选时，开始日期和结束日期必须始终显示当前已应用范围。
- 在高级筛选修改并应用日期后，右上角控件同步更新。
- 切换 7/30/90 天预设后，高级筛选中的两个日期同样同步为预设实际边界。
- 取消选择、按 Escape 或点击选择区域外部时，不修改当前已应用范围。

### 日期边界

- 起止日期均按香港时区解释，并包含所选首尾日期。
- 结束日期不得早于开始日期。
- 起止日期均不得晚于香港当前日期。
- 固定历史范围刷新时不漂移；包含今天的范围刷新时重新锚定当前时刻。

## 单一 Tooltip 交互

鼠标和键盘使用不同的状态来源，但共用相同内容格式：

- 鼠标悬停只激活图表库 Tooltip。
- 键盘聚焦数据点只激活自定义无障碍 Tooltip。
- 指针开始移动时清除键盘提示状态；数据点失焦时也清除键盘提示。
- 任意时刻最多显示一个 Tooltip 和一条十字参考线。
- Tooltip 继续一次显示当前时间桶和全部可见序列；视觉隐藏数据表继续为辅助技术提供完整数据。

## 事件明细同期比较

筛选结果、成功事件、失败事件和独立访客四张卡都使用完整筛选范围，并在启用同期比较时显示
上一等长周期的变化：

- 当前值和上期值相同：显示“与上期无变化”，不显示含义不明的符号。
- 上期没有数据：显示“暂无同期数据”。
- 比较关闭：显示“未启用同期比较”。
- 上期为 0、当前大于 0：不计算无穷百分比，显示带符号绝对变化。
- 失败事件增加使用警示色，减少使用正向色；其他三张卡沿用增长向上、下降向下的普通数量语义。
- 当前页面分页不影响四张卡；卡片不能从当前 50 条结果推算。

## 稳定性 & 时延

### 顶部指标

保留总请求、成功率、P50、P95、失败请求、Dropped 六张卡。P50、P95 数值必须直接带 `ms`
单位；较上期变化采用“时延越低越好”的颜色语义。

### 响应时间趋势

- 默认选择 P95，允许在图表自己的筛选器中切换 P50 或 P95。
- 任意时刻只绘制一个分位值，四条序列分别代表主页访问、地点查询、路线查询和下载请求。
- 图例只显示事件类型，Y 轴和 Tooltip 明确使用 `ms`。
- 某事件在时间桶内没有样本时留空，不绘制为 0。
- 切换分位值只改变本图，不改变全局筛选或其他图表。

### SLI 成功率

在响应时间趋势右侧增加“SLI 成功率”折线图：

- 四条序列分别代表主页访问、地点查询、路线查询和下载请求。
- 每个时间桶使用 `成功 PV ÷ 总 PV`。
- 没有事件的时间桶为无数据，不显示为 0%。
- 结果以百分比显示，不增加 SLA 目标线。

### 公开接口效能

端点表在当前请求数、成功率、P50、P95 之外增加：

- `P50 较上期`
- `P95 较上期`

比较规则：

| 边界 | 展示 |
|------|------|
| 当前时延高于上期 | 红色向上箭头，优先显示百分比 |
| 当前时延低于上期 | 绿色向下箭头，优先显示百分比 |
| 当前与上期相同 | 灰色横向状态及“无变化” |
| 上期为 0、当前大于 0 | 红色向上箭头和绝对毫秒变化，不显示无穷百分比 |
| 当前为 0、上期大于 0 | 绿色向下箭头和 `-100%` |
| 上期没有样本 | “暂无同期数据” |
| 当前没有样本 | 当前值与比较均显示无数据 |

颜色不是唯一线索；箭头方向、带符号数值和文字状态同时存在。

## 系统状态

删除重复的“存储概况”和“SQLite 明细存储”双重表达，只保留一个“SQLite 明细存储”主区块；
删除“隔离与降级路径”区块。

### SQLite 明细存储

- 总明细数
- 今日明细数（香港当日）
- 数据文件大小
- 最后成功写入时间

### SQLite 运行信息

- SQLite 版本
- Journal Mode
- 当前 Schema 版本

### 服务进程与监听器

- 进程启动时间
- 进程运行时长
- 进程启动以来 Dropped 数
- 私有监听器状态和监听地址

页面不得展示数据库绝对路径、签名密钥、内部错误原文、客户端网络标识或请求内容。固定配置事实
不得伪装成动态健康检查。

## 流量与试查

顶部改为六张指标卡：

1. 主页浏览 PV
2. 主页浏览 UV
3. 地点查询 PV
4. 地点查询 UV
5. 路线查询 PV
6. 路线查询 UV

PV 包含成功和失败事件；UV 按匿名 Visitor ID 在完整筛选范围内去重，不代表自然人。既有
“浏览与成功试查趋势”继续展示主页 PV、主页 UV、成功路线查询 UV，本轮不改变该趋势口径。

## 访客明细

访客页四张摘要卡严格恢复 Figma 原型：

1. 首次出现
2. 最后出现
3. 会话
4. 累计事件

事件构成继续展示四类事件分布。“常见分类”改为“访客偏好”，只展示：

- 语言
- 平台
- 装置

平台只由已有下载归因数据派生；访客没有下载事件时明确显示“暂无平台数据”，不得从装置或
User-Agent 猜测操作系统。来源信息不再占用“访客偏好”区块，仍可在事件时间线中查看。

## 私有查询契约变化

不新增端点，扩展既有私有响应：

- **Events**：在完整筛选范围摘要旁返回四项可比较指标，上一周期使用同样筛选条件。
- **Traffic**：增加地点查询总 UV、路线查询总 UV，并继续返回各自 PV。
- **Performance**：端点 P50/P95 增加上期值、绝对变化和可空变化率；增加按时间桶、事件类型
  计算的 SLI 成功率序列。
- **System**：增加香港今日明细数、SQLite 版本、Journal Mode、Schema 版本和进程运行时长所需
  的非敏感字段。

所有修改必须先进入后续 feature 的 OpenAPI 3.1 权威源，再同步到
`shared/contracts/openapi/analytics-monitoring-api.openapi.yaml` 及 bundle。生成的 API UI 中
项目可控标题、摘要、字段说明、错误说明和示例继续使用简体中文。

## 状态、局部降级与错误

- 日期校验失败时不发起查询，并在控件附近给出三语说明。
- Performance 主查询成功但 System 辅助查询失败时，只让 Dropped 指标局部不可用。
- System 的某个运行信息不可取得时，对应值显示明确无数据，不把整页伪装为不可用。
- 当前或上期缺少样本时使用空值和文字状态，不使用 0 或 Figma 示例数值掩盖缺失。
- 私有 Dashboard 查询失败不得影响公开主页、路线试查或安装包下载。

## 三语、响应式与可访问性

- 新导航、日期流程、比较状态、SLI、系统字段、六张流量卡和访客偏好全部覆盖
  `zh-Hant`、`zh-Hans`、`en`。
- `zh-Hant` 使用香港监控和产品界面常用书面语；英文使用自然、克制的产品表达。
- 桌面以 1440×1200 验证六列指标、双图并排和端点表；手机以 390×844 验证日期两步流程、
  指标卡纵向重组、图表选择器和完整导航可达性。
- 日期、图表分位选择和分页等触控目标至少 44px。
- 图表 Tooltip 同时支持鼠标与键盘，但任意时刻只显示一个。
- 变化不能只用颜色表达，必须同时有方向、数值和文字。

## 验证策略

### 行为验证

- 鼠标悬停与键盘聚焦各只显示一个 Tooltip。
- 自定日期按开始、结束顺序完成，右上角与高级筛选双向同步。
- 事件四卡、时延卡和端点表覆盖增长、下降、持平、上期为 0、无同期样本和比较关闭。
- P50/P95 切换不影响其他图表，默认 P95。
- SLI 无事件桶留空，六张流量卡和访客偏好口径正确。
- System 对单个不可用字段局部降级且不泄露敏感信息。

### 视觉验证

- 桌面：1440×1200。
- 手机：390×844 交互视口，并通过长页面截图核对完整内容。
- 三语分别验证导航、长日期范围、表头、比较文案和无数据状态不截断。
- Figma 导入画板与实施截图逐区块对照，不使用设计示例值作为运行回退。

### 契约与性能验证

- feature 与 shared OpenAPI 均通过 lint 和 bundle。
- 事件摘要、流量 UV、端点比较、SLI 和系统信息均在现有长期明细规模上按需计算。
- 以长期不超过 100 万行、日增不超过 1,000 条为验收规模，常用私有查询 95% 在 1 秒内完成。

## 范围外事项

- 不修改“34 条事件与趋势少量数据”的既有趋势口径。
- 不新增匿名事件类型、IP、User-Agent、Referrer 原文、查询词、地点、坐标或设备指纹。
- 不增加退出统计、清理、备份、导出、删除、编辑、汇总表、缓存、队列或后台聚合。
- 不新增公开或私有 HTTP 端点。
- 不修改公开主页、路线试查和 APK 下载的业务响应语义。
- 本设计阶段不开始生产代码实现或部署。
