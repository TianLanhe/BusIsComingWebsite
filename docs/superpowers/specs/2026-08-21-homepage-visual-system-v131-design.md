# BusIsComing 首页视觉系统 v1.3.1 设计合同

日期：2026-08-21

状态：视觉方向、双端构图与非理想状态均已获用户确认；Figma 尚待通过 html.to.design 导入并回填真实节点。

取代范围：本文件取代 `2026-07-20-homepage-breathing-hierarchy-redesign-design.md` 对公开首页信息架构、视觉、动效和文案的设计结论。旧文件只解释历史决策，不得继续指导实现。

## 1. 目的

本设计把 BusIsComing 公开首页重构为一条清晰、克制的产品叙事：

1. 第一屏用五个真实功能故事建立产品价值，并立即提供下载与路线试查；
2. 第二屏让用户直接试查巴士路线；
3. 第三屏承接试查结果，完成 Android 下载转化；
4. 页面末端用轻量 FAQ、联系入口和浅色页尾消除疑虑，不再增加营销屏。

设计必须同时满足：

- 背景有可感知的风带和波浪呼吸感；
- 视觉克制、精简、安静，不堆砌卡片；
- 页面层级强，用户第一眼知道先看标题、主要行动和产品截图；
- 电脑与手机均可完整使用，手机不是桌面版的简单缩放；
- 正式实现与获批预览及后续 Figma 画板保持同一视觉合同，不得自行漂移。

## 2. 产品事实与表达边界

### 2.1 产品定位

网站统一将 BusIsComing 定位为“香港巴士路线规划与导航 App”。公共品牌表达使用“巴士”，不得把产品名称或主要定位绑定为 Citybus App。未来增加运营商时，不需要重写品牌层。

当前事实必须精确表达：

- 路线规划以当前 App 已支持的香港巴士路线数据为准；
- 符合条件的联营路线可集中显示城巴、九巴与龙运的首程到站时间；
- 上述跨运营商到站信息不等于已经支持九巴或龙运的完整路线规划；
- 网站路线试查是快速入口，App 继续承载常用行程、沿途路线与位置、完整班次及锁屏监控等能力；
- 当前公开下载是 Android APK，iPhone 版本尚未推出。

不得出现：

- “只是一款 Citybus 查询工具”一类已经过时的品牌定位；
- 暗示已经覆盖全部香港巴士运营商或全部路线的数据承诺；
- 无法由当前源码、共享契约或下载 manifest 证明的版本、大小、日期、覆盖范围或隐私承诺；
- Android 工程的本地绝对路径、内部实现路径或调试信息。

### 2.2 五个核心故事

以下繁体中文标题与说明已由用户提供并确认，属于首屏固定内容合同：

| 编号 | 标签 | 标题 | 说明 |
| --- | --- | --- | --- |
| 01 | 搜尋 | 隨心搜尋，出發更輕鬆 | 輸入起終點，即時比較合適路線 |
| 02 | 行程 | 常走的路，一按更省心 | 路線、車費與候車時間集中比較，選擇更清楚 |
| 03 | 沿途 | 一路看清，出行更安心 | 路線、轉乘與目前位置，沿途心中有數 |
| 04 | 班次 | 班次看得全，候車更從容 | 城巴、九巴與龍運到站時間集中呈現 |
| 05 | 出門 | 不用盯手機，出門更有把握 | 啟動一次，鎖屏持續更新候車與步行時間 |

`zh-Hans` 与 `en` 必须分别自然改写并进行独立审校，不能只做繁简转换或逐字翻译，但信息含义不得超出此表。

## 3. 整页信息架构

公开首页只保留以下四段主结构：

1. `HeroStory`：产品身份、五个功能故事、下载、路线试查和 App 截图舞台；
2. `RouteTrial`：可真实操作的网站路线试查；
3. `DownloadDecision`：Android APK 下载与安装帮助；
4. `SupportEnding`：FAQ、联系入口、隐私入口和页尾。

不再保留独立的功能网格、证明条、使用场景卡或第三个连续故事屏。五个功能故事已经在首屏完成产品价值说明，继续重复只会削弱层级。

页面阅读顺序固定为：

```text
品牌与导航
  → 当前故事标题与说明
  → 下载 / 路线试查
  → 当前 App 截图
  → 五个故事切换
  → 网站路线试查
  → Android 下载
  → FAQ / 联系 / 页尾
```

## 4. 全局视觉系统

### 4.1 视觉语气

关键词是“有空气流动的安静工具”，不是科技展板、营销长页或玻璃卡片集合。

- 使用海绿、深青、白和极浅绿色；
- 不使用紫色、蓝紫渐变、霓虹光晕或离散彩色色块；
- 不在页面底部放置深色潮汐、固定波浪或假结尾；
- 背景风带允许贯穿前三屏，但随叙事推进逐渐收敛；
- 卡片只用于路线结果等确实需要边界的重复信息，不把普通文案包装成卡片。

参考色彩语义：

| 语义 | 参考值 | 使用范围 |
| --- | --- | --- |
| 主文字 | `#102827` | 标题、重要数字、正文高强调 |
| 品牌海绿 | `#08645d` | 主按钮、选中态、焦点、关键连线 |
| 深青 | `#073f3c` | 次级按钮文字、强调边框 |
| 次要文字 | `#58706d` 至 `#607875` | 说明与元信息 |
| 浅绿背景 | `#d4e9e4` 至 `#f1f7f4` | 风带舞台和段落过渡 |
| 纸面背景 | `#f8fcfa` | FAQ 与页尾 |

正式实现应从共享 token 管理颜色与间距；以上值是获批预览的视觉基线，不应在组件内重复散落。

### 4.2 排版层级

- 首屏五个故事标题是全站最大层级，桌面使用 `clamp(54px, 6.3vw, 92px)` 并根据语言收敛；手机使用 `clamp(37px, 10.7vw, 44px)`。换行、最大宽度和一屏完整构图共同约束字号，不能仅按 viewport 线性放大。
- 路线试查标题低于首屏标题，但仍承担第二主任务的开场。
- 下载标题刻意比前两屏轻：桌面 `53px / 1.10 / -0.04em`，手机 `36px / 1.09 / -0.035em`。
- FAQ 标题桌面约 `54px`、手机约 `39px`，正文和折叠项保持清晰但不竞争下载入口。
- 下载版本号与右侧 Android、大小、日期信息使用相同的小字号；不得单独放大版本号。

### 4.3 风带背景

风带由三至五层不同距离的浅色形状组成：

- 远层：大面积白色椭圆边界，低透明度、较强模糊；
- 中层：浅海绿或白色横向带，缓慢平移并轻微缩放；
- 近层：更亮但更窄的白色呼吸层；
- 呼吸光层：低饱和绿色径向光，只加强空间深度，不成为色块。

持续动画周期约 `10–22s`，使用 `transform` 和 `opacity`。不得高频闪烁、改变文字对比度或引发 layout。`prefers-reduced-motion: reduce` 下关闭持续动画，保留同色静态构图。

## 5. 第一屏：五故事 Hero

### 5.1 桌面构图

- Header 与品牌同屏，右侧完整显示“功能”“常见问题”“联系我们”和三语切换；
- 左侧依次显示产品 kicker、当前故事标题、短说明、下载主按钮、路线试查次按钮和小号 APK 元信息；
- CTA 位于标题说明与故事切换之间，不放在右上角；
- 右侧是当前故事的主手机截图，允许保留一块低权重的场景说明卡作为桌面辅助信息；
- 五个故事按钮位于左侧下方，横向连成一条有节奏的轨道；存在感高于原 A 方案的小圆点，但低于 C 方案贯穿全屏的长卷；
- 故事切换同时更新标题、说明、主图和桌面辅助卡，不能只更换图片。

### 5.2 手机构图

手机端必须在一个主要 viewport 内同时建立以下顺序：

1. 品牌与完整导航同一行；
2. 当前故事标题与说明；
3. 下载与路线试查；
4. 居中的 App 截图舞台；
5. 位于截图下方的五个故事按钮。

约束：

- 导航不得退化为只剩“联系我们”的入口，也不得压缩成含义不明的“菜单”；
- 手机截图的上下、左右边框必须完整可见，故事按钮不得覆盖截图底部；
- 不显示“功能 01 / SEARCH”一类额外功能标签；
- 不显示低存在感的“证据标签”或占据大量空间的说明卡；
- 不显示灵动岛、刘海或系统硬件开孔，只保留 App 截图与高级、简洁的手机边框；
- 手机边框使用深青金属感渐变、细高光和克制阴影，不使用厚重纯黑塑料边框。

### 5.3 环形舞台轮播

五张截图不是从前到后排成队列，而是分布在一个不可见的环形舞台上：

- 当前截图位于舞台正前方、最大、最清晰；
- 其余截图分别位于左右后方和更远的后侧，具有不同缩放、透明度、模糊和倾斜角度；
- 用户点击故事按钮后，当前前景截图沿环形路径退到后方，目标截图从后方绕到前景；
- 转场必须同时体现 `x/y` 位移、缩放、旋转、透明度和层级变化，不能使用简单淡入淡出或横向切入切出；
- 手机环形位移使用 `880ms cubic-bezier(.18,.82,.18,1)`，透明度约 `660ms`，模糊约 `760ms`；桌面主图的轻量位移约 `520ms`，两端都不能退化为瞬间替换；
- 后景截图不得遮挡标题、CTA 或故事按钮，也不得被 viewport 左右裁断；
- reduced motion 下直接交换前后层级，取消环形位移和大幅旋转。

### 5.4 素材

首屏使用 v1.3.1 五个核心功能对应的获批截图：

- 搜索 / 路线结果；
- 常用行程；
- 路线详情、转乘与位置；
- 跨运营商首程到站时间；
- 锁屏候车与步行监控。

正式资源必须进入网站受管截图目录和 manifest，带有脱敏记录与三语 alt。不得在 runtime 从 Android 工程路径读取图片，也不得把原型图标记为真实 App 截图。

## 6. 第二屏：路线试查

### 6.1 叙事角色

第二屏不是再解释一次 App，而是让用户立即完成“输入起终点并比较合适路线”的核心体验。标题采用：

> 不用先下載，現在就試一程。

### 6.2 桌面与手机布局

- 桌面使用左侧起终点查询、右侧路线结果的工作台构图；
- 手机自然堆叠，先完成地点选择和查询，再显示结果；
- 背景继续使用浅色风带，但视觉运动低于首屏；
- 查询结果使用必要的白色路线卡，卡片之间有明确但轻量的层级；
- 原型中的地名、路线号、车费、时间只用于视觉设计，正式页面必须使用真实服务返回的数据或可追溯测试 fixture。

### 6.3 路线卡合同

路线卡优先展示：

- 路线号或路线组合；
- 上下车站或路线摘要；
- 预计候车；
- 车费；
- `耗时 N 分钟`；
- `步行 N 米`。

明确删除：

- 耗时与步行前的时钟、行人等图标；
- “直达”“转乘”标签或摘要；
- 不能由查询服务证明的额外运营信息。

必须覆盖默认、地点候选、无效选择、加载、结果、空结果、失败和重试状态。错误时保留用户输入，不显示第三方原始错误，也不编造路线或 ETA。

## 7. 第三屏：Android 下载

### 7.1 文案与结构

标题固定为：

> 路線找到了，
>
> 把它帶在身邊。

桌面端采用居中的紧凑舞台，手机端左对齐。下载区域不是卡片，不再拆成“三步完成”，也不显示以下内容：

- “一个清楚的下载动作……”类解释段落；
- `BUILD 19`；
- “目前版本可下载”；
- `SHA 256`；
- 虚假安装进度或下载完成状态。

### 7.2 下载行动

- 主按钮文字为“下載 BusIsComing”，上方可保留小号 `ANDROID APK`；
- 按钮长度与内容匹配，不在桌面端无意义拉满；
- 版本、最低 Android、大小和发布日期同行显示，字号与权重一致；
- 桌面端二维码位于按钮右侧，与行动形成一个紧凑组合；
- 手机端隐藏二维码，避免用户在本机页面扫描自己的屏幕；
- 正式二维码必须由当前真实 APK 下载 URL 生成，原型二维码不得发布；
- 保留低权重的“查看 Android 安装说明”入口；
- 只有下载 manifest 处于 `ready` 时主按钮是原生可操作链接，`loading` 和 `unavailable` 不得伪装成可下载按钮。

### 7.3 下载动效

采用已确认的“风带汇聚”：

- 背景风带缓慢向下载行动附近收拢；
- 亮带从按钮内部轻轻掠过；
- 下载箭头可在汇聚完成时轻落一次；
- 动效循环要克制，不能出现手指、放大镜、角色插画或游戏化提示；
- reduced motion 下停用汇聚与箭头位移，按钮仍有清晰静态层级。

## 8. 页面收尾：FAQ、联系与页尾

### 8.1 结构

第三屏之后不再新增营销屏。风带逐渐减弱，页面进入浅白和极浅绿色的自然内容高度：

1. 无卡片 FAQ；
2. 联系横条；
3. 浅色极简页尾。

FAQ 桌面端为左侧标题、右侧折叠列表；手机端上下排列。标题为：

> 出發前，
>
> 也許你想知道。

### 8.2 FAQ 内容

只保留四个直接影响下载与使用决策的问题：

1. `Android APK 如何安裝？`
2. `目前支援哪些巴士資料？`
3. `網站試查和 App 有甚麼分別？`
4. `iPhone 可以使用嗎？`

默认展开第一项，同一时间最多展开一项。展开与收起约 `200–240ms`，使用加减号状态和 `aria-expanded`；键盘、触控和读屏路径等价。

运营商覆盖答案必须维持第 2 节的事实边界，不得恢复 Citybus-only 旧文案，也不得把联营 ETA 扩写为完整跨运营商路线规划。

### 8.3 联系横条与页尾

- 联系入口显示“还有问题？”和“直接联系我们”，以细线和箭头表达可操作性，不放入卡片；
- 页尾保留品牌、常见问题、隐私政策和返回顶部；
- 页尾保持浅色，不使用深色块或底部波浪；
- 联系邮箱从现有内容源读取，不能在多个组件形成不同副本。

## 9. 导航与三语

- 桌面和手机 Header 都必须显示品牌、功能、常见问题、联系我们和语言入口；
- 手机可以缩小间距与字号，但不能删除核心入口或改成只显示一个含义不明的菜单；
- 语言菜单必须包含繁体中文、简体中文和 English，并保留当前页面锚点；
- 所有标题、按钮、状态、FAQ、图片 alt 与辅助标签必须进入集中 i18n 内容结构；
- `zh-Hant` 使用香港交通与产品页面习惯，`zh-Hans` 和 `en` 分别独立审校。

## 10. 可访问性与交互状态

- 手机触控目标至少 `44×44 CSS px`；
- 键盘可访问 Header、五故事按钮、查询、排序、下载、FAQ、联系和返回顶部；
- 所有自定义按钮有可见 `:focus-visible`；
- 五故事切换使用 `aria-pressed` 或等价选择语义，并通过可控 live region 宣布文字变化，不能为五张装饰后景图制造额外焦点；
- 手机截图有说明画面目的的三语 alt，纯装饰后景副本对辅助技术隐藏；
- 动效不影响文字对比度，不自动抢焦点；
- `prefers-reduced-motion` 下关闭风带持续动画、环形大位移、平滑滚动和非必要浮动。

## 11. 响应式与视觉合同

主要验收 viewport：

- 桌面：`1440×960`；
- 手机：`390×844`；
- 补充检查：最小宽度 `320px`、常见 Android 真机宽度与三语长文案。

正式实现必须保持以下不可漂移项：

| 区域 | 不可漂移合同 |
| --- | --- |
| Header | 手机与品牌同行，完整显示功能、FAQ、联系和语言 |
| Hero | 标题与 CTA 在上，截图舞台居中/右侧，五故事按钮在截图下方或左下固定位置 |
| 手机舞台 | 环形远近关系、完整边框、无灵动岛、无说明卡、无故事按钮遮挡 |
| 路线卡 | 耗时和步行使用文字，不用图标；不显示直达/转乘 |
| 下载 | 居中紧凑、版本信息同字号、桌面有真实 QR、手机无 QR、无下载卡片 |
| 收尾 | 无卡片 FAQ、联系横条、浅色 footer、无深色底浪 |

实现截图必须与获批 Figma frame 对照。允许浏览器字体栅格化造成的细微像素差，但以下情况一律判定为视觉失败：

- 标题换行与 Figma 不同；
- 主行动顺序、宽度或视觉权重改变；
- 手机截图任一边框被裁切；
- 五故事按钮覆盖截图或被放回标题与 CTA 之间；
- 前后截图退化成平面队列；
- 新增未审批卡片、标签、图标、紫色色块或深色页尾；
- 390px 出现横向滚动或导航入口缺失。

## 12. Figma 交付合同
