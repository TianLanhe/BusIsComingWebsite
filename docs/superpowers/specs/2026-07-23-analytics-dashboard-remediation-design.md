# 监控 Dashboard 体验修复设计

**日期**：2026-07-23

**后续规格目录**：`specs/011-analytics-dashboard-remediation/`

**范围**：修复网站匿名访问统计功能上线后暴露的公开开发入口、时间范围、Dashboard 字体、
指标卡、折线图、热力图及详细调查页面偏差；不改变匿名采集范围、隐私边界、长期明细、无备份、
私有访问方式或公开业务接口的 fail-open 语义。

## 背景与问题

当前实现已经具备匿名事件写入、私有 Dashboard、七个工作区和三语/双端基础能力，但验收发现：

1. Vite 开发与 preview 根路径没有进入默认繁中主页。
2. Dashboard 把查询结束时间固定在当天香港时间 00:00，导致当天新增事件无法进入指标。
3. 大量文字只有 8–11px，指标值约 20–29px，低于维护者长时间阅读监控数据的舒适尺寸。
4. 折线图缺少完整坐标轴、统一图例和可用的共享 Tooltip，可见摘要反而占用大量空间。
5. 指标卡装饰圆圈没有语义，趋势相等、无同期数据与关闭比较也没有被准确区分。
6. “流量与试查”的地点/路线指标没有直接声明 UV 口径。
7. 总览响应时间被压缩为单个全局数值，没有按原 Figma 的事件维度展示。
8. 热力图仍为“星期×小时”，不符合一天一个格子的调查目标。
9. “失败与性能”“系统状态”“事件明细”“匿名访客”没有完整还原 Figma 的信息层级和调查路径。

本次采用独立的 011 修复规格，不回改已经完成并提交的 010 规格和任务历史。

## 已确认设计决策

| 主题 | 决策 |
|------|------|
| 时间预设 | 香港自然日口径：第 N−1 天 00:00 至当前时刻，包含今天 |
| 自定义日期 | 保留 7/30/90 天预设并增加自定义起止日期，首尾日期均包含 |
| Vite 重定向 | 公开主页 dev 与 preview 的精确 `/` 使用 `302 Found` 重定向至 `/zh-hant/` |
| 字体方案 | 采用视觉比较 C：指标 40px、标签 14px、正文 15px、辅助 13px；手机指标 36px |
| 指标装饰 | 删除无语义圆圈和装饰光斑 |
| 趋势状态 | 分开表达“较上期持平”“暂无同期数据”“未启用同期比较” |
| 查询指标 | 使用“成功地点查询 UV”“成功路线查询 UV”，注明按独立浏览器去重 |
| 折线图 | Grafana 风格顶部图例、X/Y 轴、网格、十字线和共享 Tooltip |
| 总览响应时间 | 按四类事件展示成功请求 P95；P50/P95 详细趋势留在性能页 |
| 热力图 | 周一至周日从上到下、周次从左到右；一天一个格子，事件数着色，Tooltip 同时显示 UV |
| 四页还原 | 严格恢复 Figma 信息架构和布局层级，同时统一使用新字号，不复制旧小字号 |
| 交付组织 | 建立独立 011 规格；不重写 Dashboard v2，也不回改 010 历史 |

## 目标与非目标

### 目标

- 维护者能在当天事件发生后通过刷新立即看到指标变化。
- Dashboard 在桌面和手机上达到清晰、可扫描、可长时间阅读的字号层级。
- 所有折线图具有一致且可解释的坐标、图例和交互。
- 详细页面恢复原 Figma 中从异常发现到事件、访客、性能和系统状态定位的调查路径。
- 需要变化的私有查询契约有明确、可测试的 OpenAPI 3.1 权威源。

### 非目标

- 不增加新的匿名事件类型、用户身份信息、IP、指纹或查询内容采集。
- 不改变 visitor Cookie、机器人过滤、30 分钟会话边界或长期明细策略。
- 不增加汇总表、定时聚合、清理、备份、导出、删除或编辑能力。
- 不新增公开或私有 HTTP 端点；允许扩展既有私有查询响应。
- 不重做品牌、侧栏导航或公开主页主体视觉。

## 系统边界

### 公开主页开发入口

只有公开主页的 Vite dev 和 preview 环境处理根路径重定向：

- `GET /` 与 `HEAD /` 返回 `302 Found` 并通过 `Location` 指向 `/zh-hant/`。
- `/zh-hant/`、`/zh-hans/`、`/en/`、静态资源和 `/api/*` 不参与重定向。
- 监控 Vite 入口、Go 正式静态托管和生产 Caddy 行为不在本次重定向范围内。

### Dashboard 前端

前端继续作为私有监控 API 的消费者，新增或重构以下聚焦单元：

- 日期范围模型：负责预设、自定义范围、香港时区、当前时间锚点和上一周期。
- 字体与卡片 token：负责全局字号层级、指标值、趋势状态和长值收敛规则。
- 通用时间序列图：负责坐标轴、图例、十字线、共享 Tooltip、键盘聚焦和隐藏数据表。
- 按日热力图：负责星期列布局、日期格、强度图例、Tooltip 和局部横向滚动。
- 四个详细工作区：复用上述单元并各自维护清晰的信息架构，不在一个巨型页面组件内混合职责。

### 私有监控查询

不新增端点，但既有 overview、traffic、events、visitor 和 system 读模型需要覆盖恢复后的页面信息。
所有变化只存在于 loopback 私有查询边界，并同步维护 feature 与 shared OpenAPI 3.1 契约。

## 时间范围与刷新语义

### 预设范围

以 `Asia/Hong_Kong` 为唯一统计展示时区。近 7/30/90 天从第 N−1 个自然日 00:00 开始，截止
请求发生时的当前时刻，因此分别产生 7、30、90 个日期桶并包含今天。

### 自定义范围

- 开始日期从当地 00:00 起算。
- 结束日期按包含语义处理；历史日期截止到下一日 00:00，结束日期为今天时截止当前时刻。
- 不允许开始日期晚于结束日期，也不允许结束日期晚于香港当前日期。
- 固定历史范围不会随着刷新漂移；包含今天的范围会在每次请求前重新计算当前时刻。

### 刷新

- 手动刷新必须重新计算当前时间锚点。
- 总览成功载入后的 60 秒自动刷新同样重新计算，不复用首次加载时冻结的 `to`。
- 详细调查页保持只手动刷新，避免调查结果跳动。
- 上一周期使用与当前查询窗口等长、紧邻当前窗口之前的时间段。

## 字体与指标卡

### 字体层级

| 元素 | 桌面 | 手机 | 字重/说明 |
|------|------|------|-----------|
| 页面标题 | 30px | 26px | 700，保持紧凑标题行高 |
| 卡片标题 | 18px | 16px | 700 |
| 正文与表格 | 15px | 14px | 普通正文 400–500，重要单元格 600 |
| 辅助、图例、坐标 | 13px | 最低 12px | 不再使用 7–10px 可见文字 |
| 指标标签 | 14px | 13px | 650 |
| 指标值 | 40px | 36px | 760；版本等长值可收敛但不得低于 32px |

桌面仍保持 1440px 下六张指标卡并排；手机使用两列或单列重组，不通过整体缩放实现适配。

### 指标卡语义

- 删除右上角装饰圆圈和右下角装饰光斑；它们没有状态、筛选或可点击语义。
- `delta = 0`：简体“较上期持平”，繁体“與上期持平”，英文“No change vs previous period”。
- 上一周期不存在：简体“暂无同期数据”，繁体“暫無同期數據”，英文“No comparison data”。
- 比较关闭：简体“未启用同期比较”，繁体“未啟用同期比較”，英文“Period comparison off”。
- 正负变化使用方向图标、带符号数值和文字共同表达，不只依赖红绿颜色。

## 图表规范

### 通用折线图

- 图例统一放在卡片标题下方、绘图区上方。
- X 轴展示香港本地时间刻度，Y 轴展示本地化数值和必要单位。
- 绘图区提供低对比网格、可识别数据点和当前时间桶十字参考线。
- 悬停或键盘聚焦某个时间桶时，共享 Tooltip 一次展示日期/时间和全部序列值。
- 图例必须覆盖每条实际绘制序列；状态和序列不能只用颜色区分。
- 删除图表下方可见的摘要句和大段数据。辅助技术数据表保留在视觉隐藏区域。
- 无数据时显示空状态，不绘制全零趋势误导维护者。

“流量与试查”按原 Figma 展示主页 PV、主页 UV、成功路线查询 UV 三条序列。顶部指标卡分别写明
“成功地点查询 UV”和“成功路线查询 UV”，并说明 UV 是按匿名独立浏览器标识去重，不代表自然人。

### 总览响应时间

总览使用四条横向事件条展示成功请求 P95：

1. APK 元数据
2. 地点查询
3. 路线查询
4. 下载响应

每条显示事件名称、相对长度和格式化耗时。总览不同时展示 P50，以保持扫描效率；完整 P50/P95
趋势、失败分布和端点表由“失败与性能”页负责。

### 按日热力图

- 以周为列，周一至周日为七行，从上到下排列；周次从左到右。
- 每个实际日期一个格子，查询范围外的补位格为空且不计入数据。
- 颜色强度表示当天匿名事件总数；Tooltip 同时显示当地日期、事件总数和 UV。
- 只保留“少→多”的颜色强度图例，不显示可见摘要表。
- 容器不足时仅热力图绘图区横向滚动；标题、说明和图例保持固定可读。

## 详细页面恢复

### 事件明细

- 顶部恢复事件类型、结果、语言、设备、来源、日期和 Visitor ID 调查入口。
- 隐私边界提示明确列出不会保存的 IP、完整 UA/Referrer、查询词、地点、坐标、Cookie 和 token。
- 恢复筛选结果、成功事件、失败事件、独立浏览器四张指标卡；数据必须来自完整筛选范围汇总，
  不得用当前页 50 条数据推算。
- 桌面表格包含时间、事件类型、截断 Visitor ID、语言、设备、来源、状态、耗时和查看访客动作。
- 分页显示当前条目范围、总数、页位置和前后操作；每页默认 50 条。
- 手机端转为 key-value 事件卡，保留访客跳转和分页，不压缩桌面表格。

### 匿名访客

- 恢复完整 ID 搜索、复制反馈、返回事件明细和匿名浏览器身份说明。
- 恢复首次出现、最后出现、会话数、累计事件四张指标卡。
- 摘要区展示完整范围的事件类型分布及常见语言、设备、来源、平台。
- 没有下载事件时，常见平台显示明确无数据状态。
- 主区域按 30 分钟无活动边界分组展示会话时间线，事件按发生时间排列。
- 使用系统真实的 22 位匿名标识规则，不复制 Figma 示例中的旧十六进制格式。

### 失败与性能

- 恢复总请求、成功率、失败请求、全局 P50、全局 P95、进程启动以来 dropped count 六张指标卡。
- 使用通用 Grafana 折线组件展示 P50/P95 时间趋势。
- 恢复脱敏失败类型分布和端点性能表，表格包括请求数、成功率、P50、P95 与状态。
- dropped count 通过既有系统状态查询取得；该辅助查询失败时只降级对应指标，不让整页失败。

### 系统状态

- 恢复数据库、最后成功写入、dropped count、私有监听器四张顶部状态卡。
- 恢复运行状态、存储概况、隔离与降级路径三个区块。
- 动态值来自系统查询；长期保留、无备份、无写入队列、private listener 不经公网代理等使用
  “配置事实”标签，避免伪装成实时探测结果。
- 运行状态不得虚构写入队列。应说明每条事件在短 deadline 内同步尝试一次，失败后增加 dropped count。
- 页面不展示数据库绝对路径、签名密钥内容、错误原文、客户端网络标识或其他敏感信息。
- 手机端按数据库、最后写入、dropped、监听器、降级路径的优先级纵向排列。

## 私有数据契约

### Overview

总览响应增加 `latencyByEvent`，每项至少包含事件类型、成功请求数和 P95。只允许四类既有匿名事件，
没有成功样本时 P95 为空而不是 0。

### Traffic

热力图单元由 `weekday + hour` 改为逐日桶。每项包含香港日期或等价桶边界、事件总数和 UV；返回
数量必须与实际查询日期范围一致。旧 168 格星期/小时结构不再作为前端契约。

### Events

分页响应增加当前完整筛选范围摘要：总事件、成功事件、失败事件和独立访客数。摘要与分页项目
使用同一筛选和时间范围。

### Visitor

访客响应增加完整范围的事件类型分布和可空常见平台。已有首次/最后出现、事件/会话数、常见
语言/设备/来源与分页时间线语义保持不变。

### Performance 与 System

性能页继续使用既有性能端点的 metrics、latency series、failures 和 endpoints，并并行读取 system
的 dropped count。系统响应补充页面所需的非敏感运行状态和存储概况；动态健康与固定配置事实
在字段和文案上分离。

所有修改必须先进入 `specs/011-analytics-dashboard-remediation/contracts/` 下的 OpenAPI 3.1
权威源，再同步至 `shared/contracts/openapi/`。生成的 API UI 中项目可控文案继续使用简体中文。

## 状态、错误与局部降级

- 页面继续区分 loading、no data、no results、query failed 和 storage unavailable。
- 自定义日期错误在控件附近说明，提交前不发查询。
- 普通失败重试保留日期、筛选、语言和当前工作区。
- 单个辅助数据源失败时优先局部降级；例如性能页 system 失败只影响 dropped count。
- Dashboard 查询失败不得改变公开主页、路线试查或 APK 下载的响应。
- 不使用 0、旧缓存示例值或 Figma 示例数值掩盖缺失数据。

## 三语、响应式与可访问性

- 新增日期控件、趋势状态、UV 标签、图例、Tooltip、热力图和详细页面文案全部覆盖
  `zh-Hant`、`zh-Hans`、`en`。
- `zh-Hant` 采用香港监控与交通产品常用书面语；英文使用自然克制的产品表达。
- 桌面以 1440×1200 验证六列 KPI、高密度图表和语义表格；手机以 390×844 交互视口及长页面
  截图验证两列/单列指标、纵向卡片、事件 key-value 卡和可达分页。
- Tooltip 同时支持鼠标悬停和键盘聚焦；焦点清晰，状态不只用颜色表达。
- 手机可操作控件保持至少 44px 触摸目标；页面不出现横向整体滚动，只有热力图绘图区允许横向滚动。

## 验证设计

### 入口与时间

- dev 与 preview 分别验证 `/` 的临时重定向、Location 和非根路径不受影响。
- 固定在香港时间 00:30 的测试必须证明当天 00:00 后事件进入总览。

## 风险与控制

- **大字号挤压六列 KPI**：长值使用受控 32px 下限和断点重组，不回退到小号正文。
- **多序列图表过密**：顶部图例、共享 Tooltip 和按页面限定序列数量，手机保持同等数据但允许图表横向更宽。
- **自定义日期时区偏移**：所有边界由香港本地日期显式转换，不依赖浏览器所在时区的午夜。
- **恢复页面时虚构健康值**：动态状态必须由私有查询提供；固定架构事实单独标注。
