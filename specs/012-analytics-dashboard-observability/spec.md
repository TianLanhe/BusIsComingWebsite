# 功能规格：监控 Dashboard 数据解释与技术监控增强

**功能分支**：`012-analytics-dashboard-observability`

**创建日期**：2026-07-24

**状态**：Draft

**输入**：用户描述：“修复折线图重复 Tooltip 和自定日期不可用问题，并增强事件同期比较、稳定性与时延、SLI、系统状态、流量指标、访客明细及监控导航。”

## 用户场景与测试（必填）

### 用户故事 1 - 可信地选择时间并读取图表（优先级：P1）

作为网站维护者，我希望能按顺序选择自定开始日期和结束日期，并在鼠标或键盘查看折线数据时只
看到一个清晰提示框，从而确信当前图表对应正确时间范围且不会因重复浮层误读数值。

**优先级原因**：时间范围和 Tooltip 直接决定所有监控数据是否可理解；若二者不可信，其他新增
指标即使正确也无法支撑调查。

**独立测试**：选择“自定日期”，依次完成开始和结束日期，确认 Dashboard 立即刷新、右上角和
高级筛选显示相同范围；再分别用鼠标悬停和键盘聚焦折线点，确认每次只显示一个 Tooltip。

**验收场景**：

1. **给定** Dashboard 当前使用近 30 天预设，**当** 维护者选择“自定日期”并选定开始日期，
   **则** 系统进入结束日期步骤，并保留已选开始日期。
2. **给定** 已选开始日期，**当** 维护者选定合法结束日期，**则** 系统立即应用且只刷新一次，
   右上角显示起止日期。
3. **给定** 已应用自定范围，**当** 维护者展开高级筛选，**则** 开始和结束日期输入显示相同范围。
4. **给定** 任意带数据的折线图，**当** 维护者用鼠标悬停数据点，**则** 页面只显示一个鼠标
   Tooltip。
5. **给定** 任意带数据的折线图，**当** 维护者用键盘聚焦数据点，**则** 页面只显示一个键盘
   Tooltip，且内容与鼠标提示使用相同数据口径。

---

### 用户故事 2 - 调查稳定性与时延变化（优先级：P1）

作为网站维护者，我希望在“稳定性 & 时延”工作区分别查看 P50 或 P95、四类事件的 SLI 成功率，
以及每个公开接口相对上期的 P50/P95 变化，从而快速判断问题属于整体成功率、尾时延还是某个
具体接口。

**优先级原因**：该工作区承担异常定位的核心路径，必须避免混合分位值并提供有边界语义的同期
比较。

**独立测试**：打开“稳定性 & 时延”，确认默认 P95、单位、SLI 四条序列和端点比较列；切换到
P50 后只改变该图，并使用包含上期为零、持平和无同期样本的 fixture 验证显示。

**验收场景**：

1. **给定** 页面首次打开且有性能数据，**当** 图表完成载入，**则** 响应时间趋势默认只显示
   四类事件的 P95，Y 轴和 Tooltip 均明确使用毫秒。
2. **给定** 当前显示 P95，**当** 维护者切换为 P50，**则** 图表只显示 P50，其他页面筛选和
   SLI 图不改变。
3. **给定** 某时间桶内四类事件均有请求，**当** SLI 图载入，**则** 每类事件显示
   `成功 PV ÷ 总 PV` 的独立序列。
4. **给定** 某类事件在时间桶内没有请求，**当** SLI 图载入，**则** 该点显示为无数据而不是
   0%。
5. **给定** 端点当前时延高于上期，**当** 维护者查看比较列，**则** 页面用警示色向上箭头、
   带符号变化值和文字共同表达变慢。
6. **给定** 上期值为 0，**当** 当前值大于 0，**则** 页面显示绝对毫秒变化，不显示无穷百分比。

### 用户故事 3 - 比较事件和业务流量（优先级：P2）

作为网站维护者，我希望事件明细摘要能展示同期变化，并在“流量与试查”直接看到主页、地点查询
和路线查询各自的 PV 与 UV，从而区分事件量变化和独立访客变化。

**优先级原因**：这能补齐日常业务监控信息，但不阻塞时间范围与稳定性调查主路径。

**独立测试**：在启用同期比较时查看事件四张卡和流量六张卡，确认值来自完整筛选范围且 PV/UV
定义明确；关闭比较后确认所有卡片显示正确关闭状态。

**验收场景**：

1. **给定** 事件明细启用同期比较，**当** 页面载入，**则** 筛选结果、成功事件、失败事件和
   独立访客四张卡都显示当前值及可解释的比较状态。
2. **给定** 失败事件比上期增加，**当** 页面载入，**则** 失败卡使用警示语义；失败事件减少时
   使用改善语义。
3. **给定** “流量与试查”有主页、地点和路线事件，**当** 页面载入，**则** 顶部显示六张
   PV/UV 卡，PV 包含成功与失败，UV 按匿名 Visitor ID 去重。
4. **给定** 既有“浏览与成功试查趋势”，**当** 本功能上线，**则** 其主页 PV、主页 UV、
   成功路线查询 UV 三条序列保持不变。

### 用户故事 4 - 查看技术运行状态（优先级：P2）

作为网站维护者，我希望“系统状态”聚焦 SQLite 明细存储、运行信息、服务进程与私有监听器，
从而在不接触敏感路径和错误原文的情况下判断存储是否正常、数据是否仍在写入。

**优先级原因**：技术状态有助于解释监控数据缺失或写入下降，但在业务统计正常时不是第一调查
入口。

**独立测试**：打开系统状态，核对总明细、香港今日明细、主数据文件大小、最后写入、SQLite
版本、Journal Mode、Schema 版本、进程运行时间、Dropped 和监听器状态；确认没有重复区块或
敏感信息。

**验收场景**：

1. **给定** 存储可用，**当** 页面载入，**则** “SQLite 明细存储”同时显示总明细数、今日明细
   数、文件大小和最后成功写入。
2. **给定** 系统查询成功，**当** 页面载入，**则** SQLite 运行信息、进程信息和私有监听器状态
   均可定位。
3. **给定** 某个运行信息无法取得，**当** 其他信息仍可用，**则** 页面只把该值标为无数据，
   不把所有已取得信息清空。
4. **给定** 系统状态页面，**当** 维护者浏览全部内容，**则** 不存在重复“存储概况”或
   “隔离与降级路径”区块，也不显示数据库绝对路径、密钥、客户端网络标识或内部错误原文。

### 用户故事 5 - 按原型调查访客明细（优先级：P3）

作为网站维护者，我希望“访客明细”按照 Figma 原型先展示首次出现、最后出现、会话和累计事件，
并通过“访客偏好”查看语言、平台和装置，从而快速理解一个匿名访客的时间跨度与使用偏好。

**优先级原因**：这是从事件继续深入调查单一 Visitor 的路径，使用频率低于整体流量与稳定性，
但必须与已确认原型一致。

**独立测试**：查询一个具有多类事件、多个会话和下载事件的 Visitor，确认四张摘要卡和三项偏好；
再查询没有下载事件的 Visitor，确认平台显示明确无数据。

**验收场景**：

1. **给定** 已查到匿名 Visitor，**当** 页面载入，**则** 四张摘要卡依次展示首次出现、最后
   出现、会话和累计事件。
2. **给定** Visitor 有语言、装置和下载平台数据，**当** 维护者查看“访客偏好”，**则** 页面
   展示最常见语言、平台和装置。
3. **给定** Visitor 没有下载事件，**当** 页面载入，**则** 平台显示“暂无平台数据”，不从装置
   或其他字段猜测。
4. **给定** 维护者使用任意支持语言，**当** 打开侧栏，**则** 能在业务监控、技术监控和数据
   明细三个分组中定位对应页面。

### 边界情况

- 当浏览器不允许在开始日期选定后自动打开第二个原生日期选择器时，系统必须保留“选择结束日期”
  状态，并让用户通过一次明确点击继续。
- 当用户在日期选择流程中按 Escape、点击外部或取消时，系统不得修改已应用范围。
- 当开始日期晚于结束日期或任一日期晚于香港当天时，系统必须在发起查询前阻止应用并说明原因。
- 当自定范围跨年时，右上角必须展示两个完整年份；手机缩写不得造成年份歧义。
- 当鼠标悬停期间仍有数据点保留键盘焦点时，系统必须以最近的输入方式为准且只显示一个 Tooltip。
- 当比较关闭、上期没有样本、当前没有样本、数值持平或上期为 0 时，各指标必须使用独立、明确的
  文字状态。
- 当时延下降时属于改善，上升时属于恶化；失败请求则相反，不能用统一“数值增加即正向”规则。
- 当 SLI 的分母为 0 时，结果必须为空；当分母大于 0 且成功数为 0 时，结果才是 0%。
- 当香港跨日时，“今日明细数”必须切换到新的香港自然日，不受维护者本机时区影响。
- 当 SQLite、进程或监听器的单个用户可见字段不可取得时，页面保留其他已获得数据，并对缺失项
  使用无数据状态；固定隐私事实 `publicProxy=false` 不作为可空探测字段。
- 当 Visitor 的平台出现次数并列时，系统必须使用稳定、可重复的排序规则选出结果。
- 当用户切换 `zh-Hant`、`zh-Hans`、`en` 时，当前页面、日期范围、全局筛选、分位选择和调查对象
  必须保持。
- `zh-Hant` 必须采用香港监控与产品界面常用书面语；`en` 必须使用自然克制的产品表达，不得从
  简体中文机械直译。
- 当用户在手机和电脑之间访问时，所有页面和操作保持同等功能覆盖；手机不得通过缩小桌面表格
  牺牲可读性。
- 当后续阶段查找设计依据时，必须能从本 feature 的 Figma 追溯文档定位文件、既有锚点、v1.3
  画板定义、交互状态和双端 viewport。
- 当私有监控响应发生变化时，必须能从本 feature 的权威接口契约定位字段、空值语义、错误格式
  和示例。
- 服务端内部错误或 panic 不得作为业务控制流；现有 HTTP recovery、请求日志和脱敏要求继续生效。

## 宪法对齐（必填）

- **产品来源**：匿名统计产品事实来自 `specs/010-website-analytics/`，当前 Dashboard 行为和
  Figma 基线来自 `specs/011-analytics-dashboard-remediation/`、本 feature 的设计文档及 Figma
  追溯；Android 主项目仅作为 BusIsComing 产品事实来源，本次不改变 App 能力描述。
- **产品范围**：本功能服务网站主页、路线试查和安装包下载的匿名监控与维护调查，不改变公开
  用户功能。
- **排除范围**：不提供完整出行路线规划，不增加地铁、铁路、渡轮或其他交通工具查询；不改变
  公开查询范围。
- **前后端边界**：前端负责日期流程、导航、图表和状态表达；后端负责当前/上期聚合、UV、时延、
  SLI 与系统运行快照；二者通过私有监控契约协作，不新增公开能力。
- **API 文档**：在 `specs/012-analytics-dashboard-observability/contracts/` 更新私有监控
  OpenAPI 3.1 权威源，保持既有 operationId；实现阶段同步到
  `shared/contracts/openapi/analytics-monitoring-api.openapi.yaml` 及 bundle，并用中文 API UI、
  lint 和 bundle 验证标题、字段、空值、错误和示例。
- **服务端 DDD 边界**：匿名统计 bounded context 继续由领域层定义日期、比较、PV/UV、分位值和
  SLI 规则；应用层编排当前/上期查询与读模型；基础设施层提供明细筛选和非敏感运行快照；接口
  适配层只负责私有 HTTP 参数、响应和错误映射，依赖方向不得反转。
- **服务端稳健性**：不得以 panic 表达业务错误；私有 HTTP 入口继续使用 recovery 与请求日志；
  本功能不需要自建 goroutine、后台任务或定时聚合。错误日志不得包含数据库路径、Visitor ID、
  请求内容、客户端 IP、完整 UA/Referrer、密钥或内部响应原文；系统状态契约明确要求的
  loopback 监听地址不是访客或事件网络标识。
- **代码可读性**：日期两步状态、Tooltip 输入方式互斥、比较零值/空值、时延好坏方向、SLI 空桶、
  香港今日边界和平台并列规则需要中文注释；简单渲染与自解释赋值不添加噪音注释。
- **三语范围**：新增或修改导航分组、页面名称、日期步骤、比较状态、P50/P95、SLI、系统字段、
  六张流量卡、访客偏好和无数据文案，全部覆盖 `zh-Hant`、`zh-Hans`、`en`；繁中和英文分别进行
  香港语境与英语产品语气审校。
- **UI 可视化**：批准的总体验和日期流程 mock 位于
  `visuals/dashboard-v13-remediation.svg`、`visuals/custom-date-flow.svg`，完整设计说明见
  `docs/superpowers/specs/2026-07-24-analytics-dashboard-observability-design.md`。
- **Figma 设计**：权威文件为
  [BusIsComing Website Homepage v1 Spec](https://www.figma.com/design/LAm6RjzFuFHsHFlcipx8pU/BusIsComing-Website---Homepage-v1-Spec)，
  既有节点为 `63:2118`、`67:672`、`80:151`；用户通过 import plugin 导入后的 v1.3 真实锚点
  为 `89:1310`。画板、交互状态、viewport 和已满足的导入门禁记录于 [figma.md](figma.md)。
- **双端适配**：桌面以 1440×1200 验证六列指标、双图和端点表；手机以 390×844 交互视口和长
  页面截图验证日期两步流程、纵向指标、图表筛选、导航可达与至少 44px 触控目标。
- **外部集成与降级**：本功能不新增外部服务、缓存或后台任务；Figma 仅用于设计追溯。私有监控
  查询局部失败时保留可用数据，公开主页、路线试查和下载不受影响。
- **验证与提交**：规格使用质量清单验证，无澄清标记后提交；后续实现必须覆盖三语、双端视觉、
  私有契约、100 万明细规模、局部降级、隐私哨兵和浏览器交互，并在每个 Spec Kit skill 后提交。

## 需求（必填）

### 功能需求

- **FR-001**：系统必须确保鼠标悬停折线点时只显示一个 Tooltip。
- **FR-002**：系统必须确保键盘聚焦折线点时只显示一个 Tooltip，且内容与鼠标提示采用相同
  时间桶和序列口径。
- **FR-003**：当鼠标与键盘状态同时存在时，系统必须以最近的输入方式为准并隐藏另一提示。
- **FR-004**：用户选择“自定日期”后，系统必须先要求选择开始日期，再要求选择结束日期。
- **FR-005**：浏览器无法自动打开第二个日期选择器时，系统必须提供保持上下文的一次点击继续
  入口。
- **FR-006**：合法结束日期选定后，系统必须立即应用范围且只触发一次数据刷新。
- **FR-007**：自定范围应用后，右上角必须同时显示开始和结束日期；跨年范围必须显示两个年份。
- **FR-008**：右上角日期控件和高级筛选中的两个日期字段必须双向同步，预设范围也必须同步。
- **FR-009**：取消日期流程不得修改当前已应用范围。
- **FR-010**：系统必须阻止开始晚于结束或晚于香港当天的范围，并在查询前显示三语错误说明。
- **FR-011**：事件明细的筛选结果、成功事件、失败事件和独立访客必须全部支持同期比较。
- **FR-012**：事件同期比较必须使用与当前完整筛选范围相同条件的上一等长周期，不受分页影响。
- **FR-013**：事件卡必须分别表达增长、下降、持平、上期无数据、当前无数据、上期为 0 和比较
  关闭。
- **FR-014**：失败事件增加必须使用恶化语义，失败事件减少必须使用改善语义。
- **FR-015**：“失败与性能”页面必须改名为“稳定性 & 时延”，并在三种语言中使用自然名称。
- **FR-016**：P50 和 P95 顶部指标值必须直接显示毫秒单位。
- **FR-017**：响应时间趋势必须提供仅作用于本图的 P50/P95 选择器，默认选择 P95。
- **FR-018**：响应时间趋势任意时刻只显示一个分位值，并分别展示主页、地点、路线和下载四类
  事件。
- **FR-019**：响应时间趋势在某类事件没有样本的时间桶中必须留空，不得绘制为 0。
- **FR-020**：“稳定性 & 时延”必须增加“SLI 成功率”折线图，分别展示四类事件的
  `成功 PV ÷ 总 PV`。
- **FR-021**：SLI 分母为 0 时必须返回无数据，分母大于 0 且成功数为 0 时才显示 0%。
- **FR-022**：SLI 图不得增加目标阈值线或把成功率称为 SLA。
- **FR-023**：公开接口效能必须增加“P50 较上期”和“P95 较上期”两列。
- **FR-024**：端点时延增加必须用警示色向上箭头，下降必须用改善色向下箭头，并同时提供带符号
  数值和文字。
- **FR-025**：端点时延持平必须明确显示“无变化”，不得显示含义不明的占位符。
- **FR-026**：上期时延为 0 且当前大于 0 时，系统必须显示绝对毫秒变化，不计算无穷百分比。
- **FR-027**：上期没有样本或当前没有样本时，端点表必须分别显示明确无数据状态。
- **FR-028**：侧栏必须包含“业务监控”“技术监控”“数据明细”三个分组。
- **FR-029**：“业务监控”必须包含总览、流量与试查和下载分析。
- **FR-030**：“技术监控”必须包含稳定性 & 时延和系统状态。
- **FR-031**：“数据明细”必须包含事件明细和访客明细。
- **FR-032**：原“匿名访客”必须在页面标题、导航和相关动作中改为“访客明细”。
- **FR-033**：系统状态必须删除重复“存储概况”和“隔离与降级路径”，只保留一个
  “SQLite 明细存储”主区块。
- **FR-034**：“SQLite 明细存储”必须显示总明细数、香港今日明细数、主数据文件大小和最后成功
  写入时间。
- **FR-035**：系统状态必须显示 SQLite 版本、Journal Mode 和当前 Schema 版本。
- **FR-036**：系统状态必须显示进程启动时间、运行时长和进程启动以来 Dropped 数。
- **FR-037**：系统状态必须显示私有监听器状态和监听地址。
- **FR-038**：单个系统字段不可取得时，系统必须保留其他可用字段并只对缺失项显示无数据。
- **FR-039**：系统状态不得展示数据库绝对路径、密钥、客户端网络标识、请求内容或内部错误原文。
- **FR-040**：“流量与试查”必须展示主页浏览 PV、主页浏览 UV、地点查询 PV、地点查询 UV、
  路线查询 PV、路线查询 UV 六张指标卡。
- **FR-041**：地点与路线 PV 必须包含成功和失败事件。
- **FR-042**：主页、地点和路线 UV 必须分别按匿名 Visitor ID 在完整筛选范围内去重。
- **FR-043**：既有流量趋势必须继续展示主页 PV、主页 UV、成功路线查询 UV，不改变序列口径。
- **FR-044**：访客明细的四张摘要卡必须依次展示首次出现、最后出现、会话和累计事件。
- **FR-045**：原“常见分类”必须改为“访客偏好”，并展示语言、平台和装置。
- **FR-046**：访客偏好必须使用完整 Visitor 事件范围派生的稳定最常见值。
- **FR-047**：Visitor 没有下载事件时，平台必须显示明确无数据，不得从其他字段推断。
- **FR-048**：事件构成、完整 ID 搜索、复制反馈和 30 分钟会话时间线必须继续可用。
- **FR-049**：所有新增与修改的用户可见内容必须覆盖 `zh-Hant`、`zh-Hans` 和 `en`，并保持
  当前日期、筛选、分位选择和调查对象不因语言切换丢失。
- **FR-050**：`zh-Hant` 必须符合香港监控与产品界面习惯，`en` 必须使用自然克制的英语产品
  表达，不得机械直译。
- **FR-051**：桌面和手机必须提供同等功能覆盖；手机页面不得通过整体缩放桌面表格实现适配。
- **FR-052**：所有新增日期、分位和导航操作在手机上必须提供至少 44px 的触控目标。
- **FR-053**：本 feature 必须提供可追溯 Figma 文件、既有节点、v1.3 画板定义、交互状态、
  桌面和手机 viewport；进入计划前必须回填用户导入后的真实 v1.3 锚点。
- **FR-054**：所有私有监控响应变化必须维护 feature-scoped OpenAPI 3.1 权威契约，并在实现
  阶段同步长期共享契约、中文 API UI、lint 和 bundle。
- **FR-055**：系统不得新增公开或私有 HTTP 端点，不得改变公开主页、路线试查或下载的业务响应。
- **FR-056**：系统不得新增匿名事件类型、客户端 IP、事件来源 IP、完整 UA/Referrer、查询词、
  地点、坐标、Cookie 内容、设备指纹或其他可识别数据；FR-037 规定的私有 loopback 监听地址
  仅是服务运行配置，不得用于识别访客。
- **FR-057**：系统必须继续只保存事件明细，不增加汇总表、缓存、队列、后台聚合、清理、备份、
  导出、删除或编辑能力。
- **FR-058**：复杂日期、Tooltip 互斥、比较边界、SLI 空桶、香港自然日和稳定并列规则必须有
  清晰中文说明；服务端错误继续通过受控返回、recovery 和脱敏日志处理，不使用 panic 作为
  业务控制流。

### 关键实体（涉及数据时填写）

- **日期范围选择**：维护者当前选择的预设或自定起止日期、香港时区解释、已应用状态和选择步骤。
- **比较指标**：当前值、上期值、绝对变化、可空变化率以及持平、无上期、无当前、零基线和比较
  关闭状态。
- **业务流量指标**：主页、地点查询、路线查询各自的 PV 和按匿名 Visitor ID 去重的 UV。
- **时延分位选择**：只属于响应时间趋势的 P50 或 P95 当前选择，默认 P95。
- **SLI 时间点**：时间桶、事件类型、成功 PV、总 PV 和可空成功率。
- **端点效能比较**：公开 operation 的请求数、成功率、当前 P50/P95 以及各自的上期变化。
- **系统运行快照**：明细总量、香港今日数量、主数据文件大小、最后写入、SQLite 运行信息、
  进程信息、Dropped 和私有监听器状态。
- **访客摘要与偏好**：首次/最后出现、会话、累计事件、事件构成及稳定派生的语言、平台、装置。
- **监控导航分组**：业务监控、技术监控、数据明细及其页面归属和三语名称。

## 假设

- 私有 Dashboard 仅供维护者通过既有本机/隧道方式访问，不新增登录或公网暴露方式。
- 当前周期的上一周期继续使用等长、紧邻当前范围之前的时间窗口。
- 时间展示和“今日”始终使用 `Asia/Hong_Kong`，与维护者设备时区无关。
- 浏览器原生日期选择器可用；无法自动打开第二个选择器时使用明确的一次点击继续。
- 时延统一以毫秒作为数据和展示单位，不在本功能内自动换算为秒。
- P50/P95 计算继续包含所选范围内对应事件的全部请求；成功率独立反映成功与失败。
- SLI 只描述实际成功率，不包含承诺目标，因此不称为 SLA，也不绘制目标线。
- 访客平台只来自已有下载归因；没有下载事件时平台为空。
- 系统“文件大小”指匿名统计主数据文件大小，不包含备份，因为项目不保留备份。
- Journal Mode、Schema 版本等技术信息只显示非敏感值，不暴露文件位置或内部 SQL。
- Figma v1.3 沿用既有 `Website Analytics / v1` 页面；用户已通过本地导入包完成导入并提供
  真实节点 `89:1310`。
- 本功能不需要新增 goroutine、后台任务、外部服务或缓存；若计划阶段发现必须新增，必须重新
  评审范围和稳健性门禁。
