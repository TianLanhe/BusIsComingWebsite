# 功能规格：统一 Android APK 下载入口

**功能分支**：`feat/013-unify-apk-download`

**创建日期**：2026-07-30

**状态**：Draft

**输入**：用户描述：“把页面中下部的下载对齐顶部的方式，并使用元数据接口做可用性检查。”

## 用户场景与测试（必填）

### 用户故事 1 - 两处入口都能可靠下载（优先级：P1）

作为使用手机或电脑访问主页的 Android 用户，我希望页面顶部和页面中下部的下载入口采用相同的可靠下载行为，以便无论从哪一处开始，都由浏览器下载管理器接管完整安装包，而不会停在页面内的虚假进度或 99%。

**优先级原因**：这是本次问题的直接修复目标。中下部入口在真实手机上的失败会阻断 App 下载这一主页核心转化路径。

**独立测试**：在安装包可用时，分别从页面顶部和页面中下部发起下载，确认两次都进入浏览器下载管理器、使用同一文件名与下载目标，并能获得与服务端公布大小和校验结果一致的完整文件。

**验收场景**：

1. **给定**安装包可用且可用性检查已完成，**当**用户点击页面顶部的 Android 下载入口，**则**浏览器下载管理器开始下载当前安装包。
2. **给定**安装包可用且可用性检查已完成，**当**用户点击页面中下部的 Android 下载入口，**则**浏览器下载管理器以与顶部完全相同的方式开始下载当前安装包。
3. **给定**任意一个 Android 下载入口，**当**用户发起下载，**则**页面不读取完整安装包内容、不创建临时页面内文件地址，也不展示由页面推算的下载百分比。
4. **给定**同一版本安装包，**当**用户分别使用两处入口下载，**则**得到的文件名、字节数和校验结果一致。

---

### 用户故事 2 - 下载前确认当前安装包可用（优先级：P1）

作为主页访问者，我希望下载入口先根据当前安装包元数据判断是否可用，以免在安装包缺失、元数据无效或检查失败时点击一个注定失败的入口。

**优先级原因**：统一下载行为必须同时统一可用性判断，否则顶部仍可能绕过检查，或者两处入口显示互相矛盾的状态。

**独立测试**：分别提供检查中、可用、缺失、无效和请求失败结果，确认页面顶部和中下部始终同步展示同一状态；只有可用状态可以发起安装包请求。

**验收场景**：

1. **给定**可用性检查尚未完成，**当**主页显示下载入口，**则**两处 Android 入口均显示检查中且不能发起安装包请求。
2. **给定**可用性检查返回合法且可用的安装包资料，**当**页面更新状态，**则**两处入口同时可用，并展示同一版本、大小和文件名信息。
3. **给定**可用性检查返回缺失、无效或失败，**当**页面更新状态，**则**两处入口同时显示暂不可用且不能发起安装包请求。
4. **给定**用户在同一页面停留期间切换语言，**当**下载状态与元数据没有变化，**则**系统只更新本地化文案和格式，不重复检查安装包。

---

### 用户故事 3 - 在三语和双端环境下理解下载状态（优先级：P2）

作为使用繁体中文、简体中文或英文的主页访问者，我希望在手机和电脑上都能清楚辨认检查中、可下载和暂不可用状态，并且不因状态切换造成布局跳动或误触。

**优先级原因**：状态清晰度和双端触控可用性决定用户是否会继续操作，但它建立在可靠下载和可用性判断已经成立的基础上。

**独立测试**：在 `zh-Hant`、`zh-Hans`、`en` 下，以 390px 手机和 1440px 电脑视口逐一展示三种状态，确认文案自然、操作区域完整、焦点状态可见且上下入口一致。

**验收场景**：

1. **给定**任一支持语言和任一目标视口，**当**下载状态改变，**则**两处入口的状态、文案和可操作性保持一致。
2. **给定**键盘、触控或辅助技术用户，**当**入口处于检查中或不可用，**则**其不可操作语义清楚且不会被误认为可下载。
3. **给定**入口处于可用状态，**当**用户使用键盘或触控定位入口，**则**主要操作区域不小于 44×44px，焦点和按下反馈清晰。
4. **给定**动态版本或大小文案较长，**当**页面在 390px 手机宽度展示，**则**文字不遮挡、不中断主要操作，也不会产生水平滚动。

### 边界情况

- 可用性检查响应缓慢时，两处入口保持稳定的检查中状态，不显示陈旧版本，也不预先请求安装包。
- 可用性检查成功后、用户点击前安装包被替换或移除时，浏览器可以收到下载接口的失败响应；页面不得把“检查时可用”承诺为“下载必然完成”。
- 元数据虽然返回成功，但状态、文件名、大小、版本或下载目标不符合公开契约时，页面按不可用处理。
- 用户连续点击或长按可用入口时，由浏览器负责下载交互；页面不建立额外的并行文件读取流程。
- 浏览器忽略建议文件名时，以服务端附件响应和浏览器行为为准，页面不复制或重命名完整文件。
- 用户切换 `zh-Hant`、`zh-Hans`、`en` 时，检查结果保持，版本与大小按当前语言重新格式化。
- `zh-Hant` 使用香港产品页面常用的“下載”“暫時未能下載”等表达；英文采用简洁克制的产品语气，避免机械逐句翻译。
- iPhone 的“尚未提供”状态和行为保持不变，不因 Android 下载入口调整而变成可操作。
- 手机和电脑布局都必须保证页面顶部与页面中下部两个入口可见、可辨识且状态一致。
- 后续实现者必须能从本 feature 的 Figma/可视化引用定位三种状态、两个位置和两个目标视口。
- 本功能不新增完整出行路线规划，也不扩展至地铁、铁路、渡轮或其他非香港巴士交通查询。

## 需求（必填）

### 功能需求

- **FR-001**：系统必须让页面顶部与页面中下部的 Android 下载入口使用同一下载目标和同一浏览器下载行为。
- **FR-002**：系统必须在允许用户发起下载前完成当前安装包的可用性检查。
- **FR-003**：系统必须让两处入口共享一次检查结果，并同时处于检查中、可用或不可用状态。
- **FR-004**：只有当检查结果包含合法且可用的当前安装包资料时，两处 Android 入口才可以操作。
- **FR-005**：可用状态必须在两处入口展示同一版本和本地化大小，并使用检查结果中的当前文件名与稳定下载目标。
- **FR-006**：检查中状态必须阻止安装包请求，并向用户清楚说明正在确认下载可用性。
- **FR-007**：缺失、无效或失败结果必须让两处入口同步不可用，并显示本地化的暂不可用说明。
- **FR-008**：页面不得通过读取完整安装包、生成临时页面内文件地址或页面内合成点击来启动 Android 下载。
- **FR-009**：页面不得展示或推算安装包下载百分比，也不得把服务端开始响应等同于浏览器完成下载。
- **FR-010**：用户切换语言时必须复用当前检查结果，只重新格式化版本、大小和状态文案。
- **FR-011**：所有新增或修改的用户可见文字必须覆盖 `zh-Hant`、`zh-Hans`、`en`，并通过香港繁体中文和自然英语语气审校。
- **FR-012**：两处入口的检查中、可用、不可用、焦点和触控状态必须在 1440px 电脑与 390px 手机布局中清楚可用。
- **FR-013**：Android 入口调整不得改变 iPhone 暂不支持的状态或行为。
- **FR-014**：服务端元数据和安装包下载的路径、成功响应、错误格式、完整性校验和匿名统计语义必须保持兼容。
- **FR-015**：既有公开契约文档必须删除“元数据失败时前端仍保持下载入口可用”的旧描述，明确元数据仅作为前端入口可用性门禁，而安装包下载仍由独立稳定下载响应负责。
- **FR-016**：后续实现与验收必须能够从 feature 文档定位 Figma 文件、关键状态、双端视觉基线和交互规则。

### 关键实体（涉及数据时填写）

- **下载可用性状态**：页面共享的 `检查中`、`可用`、`不可用` 三态；决定两个 Android 入口是否可操作。
- **当前安装包元数据**：可用性检查成功时提供的平台、状态、版本、文件名、大小、更新时间和稳定下载目标；仅用于状态判定与展示，不包含安装包内容。
- **下载入口**：位于页面顶部或页面中下部的同一类 Android 主操作；两者共享状态、目标和行为。

## 成功标准（必填）

### 可衡量结果

- **SC-001**：在目标手机浏览器和电脑浏览器中，分别从两处入口执行 20 次可用安装包下载，100% 由浏览器下载管理器接管，且不出现停在页面 99% 的页面内下载状态。
- **SC-002**：两处入口下载所得文件的文件名、字节数和校验结果在全部验收样本中 100% 一致。
- **SC-003**：在检查中、可用、缺失、无效和检查失败五类测试中，两处入口的可操作性和可见状态 100% 同步；非可用状态产生的安装包请求数为 0。
- **SC-004**：一次主页访问中，无论组件重挂载、两处入口同时出现或语言切换多少次，可用性检查最多发起 1 次。
- **SC-005**：在 `zh-Hant`、`zh-Hans`、`en` 和 1440px、390px 组合下，三种状态均无文字遮挡、水平滚动或小于 44×44px 的主要触控区域。
- **SC-006**：使用键盘和辅助技术检查时，100% 的不可操作状态具有明确语义，可用状态具有可见焦点并能正常发起浏览器下载。
- **SC-007**：页面运行期间不创建以临时页面内协议开头的安装包地址，不读取完整安装包内容，页面内下载进度展示数量为 0。
- **SC-008**：后续实现者可从本 feature 文档在 2 分钟内定位 Figma 文件、三个状态、两个入口位置和两个目标视口。

## 假设

- 元数据检查表示检查时刻的安装包可用性，不保证用户点击时文件仍存在，也不代表浏览器已经完成下载。
- 页面加载时自动发起一次元数据检查，检查失败后本次页面生命周期内不自动重试，也不回退到陈旧元数据。
- 现有元数据和稳定下载地址已经满足业务安全、完整性和匿名统计要求，本功能不改变其服务端结构。
- 浏览器可能采用自己的下载界面、建议文件名处理和重复下载策略，页面不覆盖这些原生行为。
- 断点续传、Range 响应、下载暂停/继续和安装完成追踪属于独立能力，不纳入本功能。
- iPhone 入口继续展示尚未提供，不新增 App Store 跳转。
