## 用户场景与测试（必填）

### 用户故事 1 - 查看包含当天的准确统计（优先级：P1）

作为维护者，我希望所有预设范围和自定义日期都按香港自然日计算，并在刷新时包含请求发生前的当天数据，以便刚发生的主页访问、试查和下载能及时进入 Dashboard，而不是要等到第二天。

**优先级原因**：当前时间上界冻结在香港当天 00:00，会直接造成维护者对实时访问量和问题趋势的错误判断，是本次最关键的正确性修复。

**独立测试**：固定香港时间为 00:30，写入当天 00:00 后的匿名事件，选择 7 天、30 天、90 天和跨月自定义范围，分别手动刷新与等待一次自动刷新；每次都能验证首尾边界、日期桶数量、当天事件及上一等长周期。

**验收场景**：

1. **给定** 香港时间 2026-07-23 00:30 且当天已有事件，**当** 维护者选择“近 7 天”并刷新，**则** 查询范围从 2026-07-17 00:00 开始、截止本次刷新时刻，并返回包含 2026-07-23 在内的 7 个日期桶。
2. **给定** 总览已成功载入，**当** 当前时间推进后触发手动刷新或 60 秒自动刷新，**则** 结束时刻使用新的当前时间，不复用首次加载时冻结的时间上界。
3. **给定** 维护者选择跨月自定义开始和结束日期，**当** 两个日期合法，**则** 首尾日期都被包含；结束日期是今天时截止当前时刻，结束日期是历史日期时截止下一日 00:00。
4. **给定** 自定义开始日期晚于结束日期或结束日期晚于香港今天，**当** 维护者准备提交，**则** 控件附近显示三语校验说明且不发送查询。

### 用户故事 2 - 快速读懂指标与趋势（优先级：P1）

作为维护者，我希望 Dashboard 的字号、指标卡、折线图、响应时间和热力图都具有一致、清晰且可解释的视觉语义，以便在桌面和手机上快速判断流量、试查、下载和性能变化。

**优先级原因**：当前 8–11px 的大量可见文字、缺失坐标和图例的折线，以及含义不明的装饰和趋势符号，会显著降低日常监控的可读性并导致误判。

**独立测试**：使用固定数据在 1440×1200 与 390×844 下打开总览、流量与试查、下载和性能页面，检查字号层级、指标卡三种比较状态、图例、坐标、共享 Tooltip、键盘焦点、四类事件 P95 和逐日热力图。

**验收场景**：

1. **给定** 桌面或手机 Dashboard，**当** 页面加载完成，**则** 指标值分别以 40px 或 36px 为基准显示，其余可见文字不小于桌面 13px、手机 12px，并且长版本值不得缩小到 32px 以下。
2. **给定** 指标变化为零、上一周期没有数据或维护者关闭比较，**当** 指标卡渲染，**则** 分别显示“较上期持平”“暂无同期数据”“未启用同期比较”的对应三语文案，且不出现无语义圆圈或光斑。
3. **给定** 一张含多条序列的折线图，**当** 维护者悬停或用键盘聚焦任一时间桶，**则** 图表显示香港时间 X 轴、数值 Y 轴、完整顶部图例、网格、数据点、十字线和包含全部序列值的共享 Tooltip。
4. **给定** 折线图存在可访问数据表，**当** 普通视觉用户浏览图表，**则** 图表下方不显示摘要句或大段数据；辅助技术仍能读取隐藏数据表。
5. **给定** 总览有四类成功请求，**当** 响应时间区域渲染，**则** 按 APK 元数据、地点查询、路线查询和下载响应分别展示 P95；无成功样本时显示缺失状态而不是伪造 0。
6. **给定** 一个 7、30、90 天或自定义范围，**当** 逐日热力图渲染，**则** 每个实际日期只有一个格子，周一至周日从上到下、周次从左到右排列，颜色表示事件数，Tooltip 同时显示日期、事件数和 UV，空间不足时只有绘图区横向滚动。

### 用户故事 3 - 完成端到端调查（优先级：P2）

作为维护者，我希望“事件明细”“匿名访客”“失败与性能”“系统状态”完整恢复已确认 Figma 的信息架构，并使用本次新字号和真实查询口径，以便从异常指标继续定位事件、会话、端点和统计存储状态。

**优先级原因**：四个页面已经存在，但关键汇总、调查入口、局部降级和系统事实缺失，无法稳定完成问题定位。

**独立测试**：从事件明细筛选一组数据，进入匿名访客会话，再查看相同范围的性能与系统状态；分别验证完整范围汇总、50 条分页、22 位匿名标识、30 分钟会话、端点性能、dropped count 局部降级，以及动态状态与配置事实的区分。

**验收场景**：

1. **给定** 事件明细存在超过一页的筛选结果，**当** 页面加载，**则** 四张指标卡基于完整筛选范围而非当前页计算，并在桌面表格或手机 key-value 卡中提供访客跳转和可达分页。
2. **给定** 维护者进入匿名访客页，**当** 输入完整 22 位 Visitor ID，**则** 页面支持精确搜索与复制反馈，展示首次/最后出现、会话数、累计事件、完整范围事件构成、可空常见平台和按 30 分钟无活动切分的时间线。
3. **给定** 维护者查看失败与性能页，**当** 性能查询成功而系统状态辅助查询失败，**则** 总请求、成功率、失败请求、P50/P95、趋势、失败分布和端点表保持可用，仅 dropped count 显示局部不可用。
4. **给定** 维护者查看系统状态，**当** 页面加载，**则** 数据库、最后成功写入、dropped count 和私有监听器显示动态状态；长期保留、无备份、无写入队列和不经公网代理显示为“配置事实”，且不暴露路径、密钥、错误原文或客户端网络标识。
5. **给定** 任一私有监控查询失败，**当** 页面进入 loading、无数据、筛选无结果、普通失败或存储不可用状态，**则** 状态含义清晰分离、保留调查上下文，并且不改变公开主页、试查或 APK 下载的响应。

### 用户故事 4 - 从默认语言进入本地公开主页（优先级：P3）

作为本地开发或验收人员，我希望公开主页的 Vite dev 与 preview 根路径自动进入繁体中文主页，以便直接打开服务地址时得到与产品默认语言一致的入口。

**优先级原因**：它影响本地验收便利性，但不改变生产 Go 静态托管、Caddy 或公开业务能力，因此排在监控正确性和调查能力之后。

**独立测试**：分别启动公开主页 dev 与 preview，使用 GET 和 HEAD 请求精确根路径，并验证本地化路径、静态资源和 API 路径保持原行为。

**验收场景**：

1. **给定** 公开主页 Vite dev 或 preview 已启动，**当** GET 或 HEAD 请求精确 `/`，**则** 返回 `302 Found`，`Location` 为 `/zh-hant/`。
2. **给定** 请求 `/zh-hant/`、`/zh-hans/`、`/en/`、静态资源或 `/api/*`，**当** Vite 处理请求，**则** 不触发根路径重定向。
3. **给定** 监控 Vite 入口或正式 Go/Caddy 环境，**当** 访问其根路径，**则** 本功能不改变现有入口行为。

### 边界情况

- 香港自然日与维护者浏览器所在时区不同、跨月或跨年时，统计边界仍以 `Asia/Hong_Kong` 计算。
- 查询范围包含今天时每次刷新推进结束时刻；固定历史范围刷新时保持原首尾边界。
- 上一周期与当前周期等长且紧邻当前周期；不足以形成上一周期时显示“暂无同期数据”，不以零替代。
- 日期范围没有事件时显示真正无数据状态；筛选后没有匹配项时显示筛选无结果状态，二者不得混用。
- 某条折线序列为空时不得伪造全零曲线；全部序列为空时显示图表空状态。
- 图表数据点过密时可扩大内部绘图区或减少可见刻度，但不得丢失真实数据点、图例或可访问表格。
- 热力图首尾周的范围外补位格为空且不计入格子数；跨越多周时仅绘图区允许横向滚动。
- 长版本号、较大的指标值和三语长文案不得溢出卡片；允许受控换行或布局重组，不得缩小至字号下限以下。
- 事件摘要、分页条目和访客摘要必须使用同一时间、事件、结果、语言、设备、来源及 Visitor ID 筛选条件。
- 常见平台没有下载事件时显示明确无数据，不推断为 Android。
- dropped count 辅助查询失败时仅降级对应指标；监控存储失败不得影响公开业务响应。
- 用户切换 `zh-Hant`、`zh-Hans`、`en` 时，保持当前工作区、日期范围、筛选和调查对象；繁中使用香港监控语境，英文保持自然克制。
- 桌面端保留高密度表格与图表；手机端使用两列/单列指标、纵向卡片和 key-value 事件卡，不整体缩放桌面布局。
- 后续 UI 迭代通过本规格 `figma.md` 找到 v1.1 真实锚点和 v1.2 差异导入包；在用户完成导入前不得虚构新节点 ID。
- 服务端私有查询契约变更必须先更新 feature OpenAPI 3.1 YAML，再同步 shared 契约、生成中文 API UI 并验证 lint/bundle。
- 服务端异常由既有 recovery 和脱敏请求日志承接；不得以 `panic` 作为业务控制流，本功能不新增无保护 goroutine。

## 宪法对齐（必填）

- **产品来源**：本功能修复既有网站匿名监控，不改变 Android App 产品事实；监控事件仍来自本仓库公开主页、地点查询、路线查询和 APK 下载。产品范围边界继续参考 `/Users/hezhenyu/AndroidStudioProjects/BusIsComming/AGENTS.md`、`README.md`，页面结构参考 010 已确认 Figma 和 `docs/superpowers/specs/2026-07-23-analytics-dashboard-remediation-design.md`。
- **产品范围**：提高主页访问、香港巴士试查与 App 下载行为的匿名监控正确性和可调查性，只服务网站维护，不增加面向公众的新功能。
- **排除范围**：不提供完整出行路线规划，不增加地铁、铁路、渡轮或其他非香港巴士交通查询；不增加事件类型、IP、指纹、查询内容、个人身份、数据导出、删除、备份或聚合表。
- **前后端边界**：公开前端只增加 Vite 本地入口重定向；监控前端负责日期模型、展示、交互、局部降级和三语响应式；后端 analytics bounded context 负责使用统一筛选生成完整范围汇总、逐日桶和非敏感读模型；双方通过私有 OpenAPI 契约协作。
- **API 文档**：扩展既有私有 monitoring API，不新增端点。权威源为 `specs/011-analytics-dashboard-remediation/contracts/analytics-monitoring-api.openapi.yaml`，包含 overview、traffic、events、visitor、performance、system 的既有 operationId、统一错误格式和简体中文摘要/参数/响应/示例；验证后同步至 `shared/contracts/openapi/analytics-monitoring-api.openapi.yaml` 并生成中文 API UI。
- **服务端 DDD 边界**：analytics 领域保持 Event、DateRange、Session、DailyBucket、PerformanceMetric 等概念；应用层查询服务组织读模型和局部降级；基础设施层通过存储端口查询 SQLite；HTTP 适配层只解析参数、调用应用服务并映射 DTO/错误，依赖方向始终指向领域与应用层。
- **服务端稳健性**：不以 `panic` 处理日期、存储或契约错误；既有公开/私有 HTTP 入口继续启用 recovery 和请求日志；不新增后台任务或无保护 goroutine；日志只记录脱敏分类和必要上下文，不记录 Visitor ID 全值、网络标识、路径或密钥。
- **代码可读性**：香港日期边界、上一等长周期、热力图补位、会话切分、完整范围摘要、动态状态与配置事实的映射必须由聚焦函数和清晰命名表达，并对不直观的外部约束与降级规则补充中文注释。
- **三语范围**：新增或修改日期预设/校验、比较状态、UV 标签、图例、Tooltip、热力图、四个调查页和状态文案，均提供 `zh-Hant`、`zh-Hans`、`en`；繁中按香港产品习惯审校，英文避免逐句直译和过度口语化。

- **Figma 设计**：权威文件为 [BusIsComing Website Homepage v1 Spec](https://www.figma.com/design/LAm6RjzFuFHsHFlcipx8pU/BusIsComing-Website---Homepage-v1-Spec)，已确认锚点为 [63:2118](https://www.figma.com/design/LAm6RjzFuFHsHFlcipx8pU/BusIsComing-Website---Homepage-v1-Spec?node-id=63-2118) 与 [67:672](https://www.figma.com/design/LAm6RjzFuFHsHFlcipx8pU/BusIsComing-Website---Homepage-v1-Spec?node-id=67-672)；v1.2 差异画板逻辑节点和导入状态记录在 `figma.md`，真实导入锚点由用户完成 plugin 导入后补录，实施不得虚构。
- **双端适配**：桌面以 1440×1200 验证六列 KPI、图表、表格和调查层级；手机以 390×844 交互视口及长页面截图验证 36px 指标、纵向卡片、事件 key-value 卡、44px 触摸目标和局部热力图滚动；页面整体不得横向滚动。
- **外部集成与降级**：不新增外部服务。Figma MCP 额度不足时使用已确认的 HTML 导入流程；私有 monitoring API 单个辅助查询失败时局部降级，整个监控存储不可用时显示明确状态；公开主页、试查和下载继续 fail-open。
- **验证与提交**：规格以需求清单、无占位符检查、Figma 导入包语法/渲染检查和 `git diff --check` 验证；通过后只提交 011 规格与设计证据，不包含用户现有 APK/版本文件改动。

## 需求（必填）

### 功能需求

- **FR-001**：系统必须以 `Asia/Hong_Kong` 为统计展示时区，将近 7/30/90 天分别计算为第 N−1 个香港自然日 00:00 至本次查询当前时刻，并返回恰好 7/30/90 个包含今天的日期桶。
- **FR-002**：维护者必须能够选择包含首尾日期的自定义范围；历史结束日期截止下一日 00:00，结束日期为香港今天时截止本次查询当前时刻。
- **FR-003**：系统必须在提交前拒绝开始日期晚于结束日期或结束日期晚于香港今天的范围，并在控件附近显示三语错误且不发送查询。
- **FR-004**：手动刷新与总览成功载入后的 60 秒自动刷新必须重新计算当前时间上界；不包含今天的固定历史范围必须保持稳定。
- **FR-005**：同期比较必须使用与当前查询窗口等长、紧邻其前的时间段，并区分“较上期持平”“暂无同期数据”“未启用同期比较”三种状态。
- **FR-006**：Dashboard 桌面/手机必须分别采用 40px/36px 指标基准，页面标题 30px/26px、卡片标题 18px/16px、正文与表格 15px/14px、辅助文字不低于 13px/12px；长指标值不得低于 32px。
- **FR-007**：指标卡必须删除无交互和无状态语义的右上圆圈与装饰光斑；变化方向必须同时使用图形、带符号数值和文字，不得只依赖颜色。
- **FR-008**：流量与试查指标必须明确标注“成功地点查询 UV”和“成功路线查询 UV”，并说明 UV 按匿名独立浏览器标识去重、不代表自然人。
- **FR-009**：所有折线图必须具有顶部完整图例、香港本地时间 X 轴、本地化数值 Y 轴、低对比网格、可识别数据点、十字线以及支持鼠标悬停和键盘聚焦的共享 Tooltip。
- **FR-010**：折线图不得在下方展示可见摘要句或大段数据；必须保留视觉隐藏的可访问数据表，且无数据时显示空状态而不是全零曲线。
- **FR-011**：流量与试查趋势必须绘制主页 PV、主页 UV、成功路线查询 UV 三条序列，并为每条实际序列提供一致图例。
- **FR-012**：总览必须按 APK 元数据、地点查询、路线查询、下载响应四类既有事件展示成功请求 P95 和成功样本数；没有成功样本时 P95 为缺失状态，不得显示 0。
- **FR-013**：流量热力图必须以一天一个格子、周一至周日七行、周次从左到右排列；颜色按事件总数分级，Tooltip 显示香港日期、事件总数和 UV，且范围外补位格不计入结果。
- **FR-014**：热力图日期较多时必须只让绘图区横向滚动，标题、说明和“少→多”强度图例保持固定，页面整体不得横向滚动。
- **FR-015**：事件明细必须提供事件类型、结果、语言、设备、来源、日期和 Visitor ID 调查入口，并显示不保存 IP、完整 UA/Referrer、查询内容、坐标、Cookie 和 token 的隐私边界。
- **FR-016**：事件明细必须返回与当前完整筛选范围一致的总事件、成功事件、失败事件、独立浏览器摘要；桌面每页默认 50 条表格，手机转为 key-value 卡，二者都提供访客跳转、条目范围、总数、页位置和前后分页。
- **FR-017**：匿名访客页必须支持 22 位完整匿名标识的精确搜索、复制反馈和返回事件明细，并展示首次出现、最后出现、会话数、累计事件、事件类型分布及常见语言、设备、来源、可空平台。
- **FR-018**：匿名访客时间线必须按 30 分钟无活动边界分组，并按发生时间展示不含查询内容和网络标识的事件；没有下载事件时常见平台必须显示无数据。
- **FR-019**：失败与性能页必须展示总请求、成功率、失败请求、全局 P50、全局 P95、进程启动以来 dropped count 六个指标，并展示 P50/P95 趋势、脱敏失败类型分布和含请求数、成功率、P50、P95、状态的端点表。
- **FR-020**：失败与性能页读取系统 dropped count 失败时必须只降级该指标，不得让性能查询和页面其他区域失败。
- **FR-021**：系统状态页必须展示数据库、最后成功写入、dropped count、私有监听器四个动态状态，以及运行状态、存储概况、隔离与降级路径三个区块。
- **FR-022**：系统状态页必须把长期保留、无备份、无写入队列、private listener 不经公网代理标记为配置事实，不得虚构写入队列或把固定配置表示成实时探测结果。
- **FR-023**：监控页面不得展示数据库绝对路径、签名密钥、错误原文、完整客户端网络标识或其他敏感信息；私有查询失败不得改变公开主页、试查和 APK 下载响应。
- **FR-024**：监控页面必须区分 loading、无数据、筛选无结果、普通查询失败、监控存储不可用，并在重试、切换语言或工作区时保持日期、筛选和调查上下文。
- **FR-025**：公开主页 Vite dev 与 preview 必须只对 GET/HEAD 精确 `/` 返回 `302 Found` 和 `Location: /zh-hant/`，不得改变本地化路径、静态资源、`/api/*`、监控入口、Go 正式静态托管或 Caddy 行为。
- **FR-026**：所有新增或修改的可见文案必须覆盖 `zh-Hant`、`zh-Hans`、`en`，在 1440×1200 与 390×844 下无缺失键、关键裁切或页面级横向溢出；手机交互目标不得小于 44px。
- **FR-027**：既有私有 monitoring API 的响应扩展必须以本功能 OpenAPI 3.1 YAML 为权威源，保持既有端点与 operationId，并同步 shared 契约、中文 API UI、示例和统一错误说明。
- **FR-028**：服务端必须保持 analytics DDD 依赖方向、HTTP recovery 和脱敏请求日志，不得以 `panic` 作为业务控制流，不得为本功能新增无 recover 保护的 goroutine。
- **FR-029**：本功能不得增加匿名事件类型、IP、指纹、完整 UA/Referrer、查询词、地点、坐标、请求体、Cookie/token 明细、公开端点、汇总表、定时聚合、清理、备份、导出、删除或编辑能力。
- **FR-030**：前端完整页面必须沿用已确认 Figma v1.1 信息架构，并使用 v1.2 差异画板校验新字体、指标状态、图表、热力图和四个调查工作区的桌面/手机片段；用户未导入前必须保留“待导入”状态且不得虚构锚点。

### 关键实体（涉及数据时填写）

- **DashboardDateRange**：维护者选择的统计时间范围，包含预设或自定义类型、香港开始时刻、结束日期、查询时动态结束时刻、是否包含今天及上一等长周期。
- **ComparisonState**：指标与上一周期的比较语义，包含正向、负向、持平、无同期数据、比较关闭，不以缺失值伪装成零。
- **TimeSeries**：一张图表中的一组时间序列，包含稳定标识、三语名称、单位、香港时间桶和可空数值；图例、Tooltip 和隐藏表格共享同一数据源。
- **DailyHeatmapCell**：查询范围内一个香港自然日的数据单元，包含当地日期、桶边界、匿名事件总数和 UV；范围外补位不属于实体集合。
- **EventRangeSummary**：与事件明细同一完整筛选范围对应的总事件、成功事件、失败事件和独立浏览器数，不受当前分页大小影响。
- **VisitorInvestigationSummary**：某个 22 位匿名浏览器标识在完整时间范围内的首次/最后出现、会话/事件数、事件类型分布和常见粗粒度分类，其中平台允许为空。
- **EventLatencySummary**：一个既有匿名事件类型的成功样本数与可空 P95，用于总览四类事件响应时间展示。
- **SystemStatusView**：由动态运行状态和明确标注的固定配置事实组成的非敏感系统视图，不包含路径、密钥和原始错误。

## 成功标准（必填）

### 可衡量结果

- **SC-001**：在香港时间 00:30 写入当天事件后，维护者在一次手动刷新或下一次 60 秒自动刷新完成后即可看到指标增加，展示延迟不超过 65 秒。
- **SC-002**：近 7/30/90 天分别渲染恰好 7/30/90 个实际日期格，自定义范围渲染包含首尾日期的准确格子数，跨月、跨年和浏览器非香港时区测试全部通过。
- **SC-003**：100% 的折线图显示完整图例、X/Y 轴、键盘/鼠标共享 Tooltip 和隐藏数据表，且图表下方没有可见摘要或大段数据。
- **SC-004**：在 1440×1200 与 390×844 三语视口中，所有指标、坐标、图例、表格/卡片和状态文字满足字号下限，无关键裁切、页面级横向滚动或小于 44px 的手机主要操作。
- **SC-005**：测试数据覆盖持平、无同期数据、关闭比较三种状态时，100% 指标卡显示正确三语文案，且页面中不再出现指标卡装饰圆圈或光斑。
- **SC-006**：总览对四类事件分别展示成功样本数和可空 P95；流量页的地点/路线指标及趋势图明确使用 UV/PV 口径，验收人员无需查看说明文档即可分辨。
- **SC-007**：维护者可在 2 分钟内从异常指标进入事件筛选、定位匿名访客会话、查看相关端点性能并确认系统状态，四个页面均包含规格列出的全部区块。

- **SC-012**：在长期明细不超过 100 万行、日增不超过 1000 行的目标规模下，私有监控页核心查询和访客时间线在本地基准环境中 95% 于 1 秒内完成。

## 假设

- 维护者访问的是不暴露公网的监控页，既有 loopback/SSH 隧道访问方式不变。
- 匿名 visitor Cookie、机器人过滤、30 分钟会话边界、长期保留、只存明细、单份数据且允许丢失等 010 决策继续有效。
- 主页访问仍只统计主页，不扩大到隐私页或其他公开页面。
- 本次不增加重新加载 APK 版本信息的操作；版本信息失败仍不得影响 APK 下载。
- 既有 010 Figma v1.1 两个真实锚点是完整页面信息架构权威；v1.2 采用本地 HTML 导入包，由用户通过 import plugin 导入同一文件后补录真实锚点。
- 设计稿中的数值只用于布局验证，运行时必须展示 API 数据，不得以示例值作为失败回退。
- 复杂日期与统计规则需要中文注释，自解释的简单布局和样式不增加噪音注释。
- OpenAPI 3.1 YAML 是私有 monitoring API 的唯一权威契约，API UI 仅用于中文预览、试接口、lint 与 bundle。
