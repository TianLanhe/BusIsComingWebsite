## 用户场景与测试（必填）

### 用户故事 1 - 第一眼理解产品并开始行动（优先级：P1）

作为第一次访问网站的香港巴士用户，我希望在第一屏立即看懂 BusIsComing 是一款香港巴士路线规划与导航 App，并能直接选择下载 Android App 或试查路线，而不需要先浏览重复的功能介绍。

**优先级原因**：第一屏承担产品识别和两项核心转化任务；如果层级、构图或文案不清楚，后续路线试查和下载内容都失去入口价值。

**独立测试**：分别以电脑和手机打开任一语言的首页，在不滚动的情况下确认品牌、当前故事标题与说明、下载、路线试查、当前 App 截图和故事切换均清楚可见且互不遮挡。

**验收场景**：

1. **给定**用户首次打开桌面首页，**当**第一屏完成展示，**则**用户先看到当前故事标题与说明，其次看到下载和路线试查行动，再看到具有前后层次的真实 App 截图。
2. **给定**用户以 `390×844` 手机视口打开首页，**当**第一屏完成展示，**则**品牌与完整导航同行，标题、说明、两个核心行动、完整手机截图舞台和位于截图下方的五个故事按钮均在主要 viewport 内建立清楚顺序。
3. **给定**用户点击任一故事按钮，**当**切换完成，**则**标题、说明、当前截图、按钮选中态和可访问性说明同步更新，目标截图从环形舞台后方转到前景，原前景截图退到后方。
4. **给定**用户未与页面交互，**当**页面停留在第一屏，**则**浅绿与白色风带以克制的远近层次持续呼吸，不出现紫色色块、深色底浪、文字对比度变化或页面布局位移。
5. **给定**用户启用减少动态效果偏好，**当**页面和故事状态变化，**则**持续风带和大幅环形位移停止，但信息层级、选中态和所有操作仍完整可理解。

### 用户故事 2 - 不下载也能试查巴士路线（优先级：P1）

作为尚未决定下载 App 的访问者，我希望在第二屏直接输入起点和终点，看到真实、可理解的巴士路线比较和受控失败状态，以便先验证产品价值再决定是否下载。

**优先级原因**：路线试查是网站除下载外最重要的核心功能，也是首屏承诺“输入起终点，即时比较合适路线”的直接兑现。

**独立测试**：从第二屏完成一次有效路线试查，并分别检查默认、地点候选、无效选择、加载、成功、空结果、失败、重试以及保留上次结果的状态。

**验收场景**：

1. **给定**用户进入路线试查，**当**选择有效起终点并查询，**则**页面在同一工作区内呈现可比较的真实路线结果，而不是重复首屏的营销故事。
2. **给定**查询成功且返回多条路线，**当**路线卡展示，**则**每张卡优先显示路线号或组合、上下车摘要、预计候车、车费、“耗时 N 分钟”和“步行 N 米”。
3. **给定**路线结果包含耗时和步行信息，**当**页面展示路线卡，**则**耗时与步行使用文字而非时钟、行人图标，且不显示“直达”或“转乘”标签。
4. **给定**外部数据暂时不可用，**当**试查失败，**则**页面保留用户已选起终点、给出单一清楚的重试路径、隐藏第三方原始错误，并且不编造路线或到站时间。
5. **给定**旧结果仍可阅读但刷新失败，**当**页面降级，**则**只在结果区域低权重说明“暂未更新”，不新增遮挡内容的警告卡。

### 用户故事 3 - 从试查自然转向 Android 下载（优先级：P1）

作为已经看到合适路线的 Android 用户，我希望第三屏自然承接试查结果，并通过一个明确、可信且有趣但克制的下载行动获得当前 App，而不是面对另一组重复卡片或虚假下载信息。

**优先级原因**：下载是网站的核心转化结果，必须承接路线试查而不是与前两屏竞争或重复解释产品功能。

**独立测试**：分别在电脑和手机检查下载可用性三态，并在可用状态确认按钮、真实版本信息、桌面二维码和安装说明均符合当前下载资料。

**验收场景**：

1. **给定**用户滚动到第三屏，**当**下载区进入视野，**则**看到“路线找到了，把它带在身边”的简洁标题和非卡片式下载行动，不出现“三步完成”或大段自我解释。
2. **给定**当前 Android 安装包可用，**当**下载区展示，**则**主按钮可直接发起浏览器原生下载；版本、最低 Android、大小和发布日期使用相同的小字号和权重。
3. **给定**桌面用户查看可用下载，**当**二维码显示，**则**二维码指向与主按钮相同的当前真实下载目标；手机端始终不显示要求用户扫描自己屏幕的二维码。
4. **给定**安装包仍在检查或暂不可用，**当**下载区展示，**则**主行动不会伪装成可下载链接，二维码不显示，页面不展示虚假进度或安装完成状态。
5. **给定**下载区保持可见，**当**背景动效运行，**则**风带缓慢向下载行动汇聚并以轻量亮带或箭头动作提示主行动，不出现手指、放大镜、人物或游戏化动画。

### 用户故事 4 - 在页面末端消除使用疑虑（优先级：P2）

作为在下载前仍有疑问的访问者，我希望在页面末端快速找到安装、数据覆盖、网站与 App 区别及 iPhone 支持情况，并能联系开发者，而不需要穿过更多营销屏。

**优先级原因**：FAQ 和联系入口帮助完成决策，但不应抢占首屏核心任务或形成第四个营销故事屏。

**独立测试**：依次展开四个 FAQ、使用键盘切换问答、进入联系与隐私入口，并确认同一时间最多展开一项。

**验收场景**：

1. **给定**用户离开下载区继续下滚，**当**进入页面收尾，**则**风带逐渐减弱并自然过渡到无卡片 FAQ、联系横条和浅色页尾。
2. **给定**FAQ 初次出现，**当**用户尚未操作，**则**“Android APK 如何安装？”默认展开，其余三项收起。
3. **给定**用户展开另一个问题，**当**新答案出现，**则**原答案收起，同一时间最多一项展开，展开状态对键盘、触控和辅助技术等价可用。
4. **给定**用户查看运营商覆盖答案，**当**阅读内容，**则**能理解符合条件的联营路线可集中显示城巴、九巴与龙运首程到站时间，但不会被误导为 App 已支持九巴或龙运的完整路线规划。
5. **给定**用户仍需帮助，**当**选择“直接联系我们”、隐私政策或返回顶部，**则**对应操作清楚可见并正常到达目标。

### 用户故事 5 - 在三语和不同设备上获得同等体验（优先级：P2）

作为繁体中文、简体中文或英文用户，我希望首页在电脑和手机上都保持同等信息、操作和自然语气，并在键盘、触控或减少动效条件下仍能顺畅完成了解、试查和下载。

**优先级原因**：三语、双端与可访问性是整页体验的横向质量门槛；任一语言或设备退化都会直接影响真实用户。

**独立测试**：在 `zh-Hant`、`zh-Hans`、`en` 下分别以 `1440×960`、`390×844` 和 `320px` 宽度完成故事切换、路线试查、下载状态识别、FAQ 和导航操作。

**验收场景**：

1. **给定**用户切换任一支持语言，**当**页面文案更新，**则**当前故事、滚动位置、路线输入、查询结果和展开 FAQ 保持，语言入口继续可发现。
2. **给定**用户阅读任一语言，**当**标题、按钮和状态展示，**则**繁体符合香港交通与产品页面习惯、简体自然、英文克制可信，不出现机械繁简转换或逐句直译。
3. **给定**键盘或辅助技术用户，**当**遍历页面，**则**完整导航、故事按钮、查询、下载、FAQ、联系和返回顶部均有正确顺序、可见焦点及可理解状态。
4. **给定**`320px` 至桌面宽度的常见 viewport，**当**页面展示任一故事和语言，**则**不出现水平滚动、重要文字截断、手机边框裁切或操作重叠。

### 边界情况

- 当手机可用宽度不足以并排展示大字号导航时，页面必须缩小间距和字号并保持全部核心入口，不得只剩“联系我们”或含义不明的菜单。
- 当繁体、简体或英文标题换行长度不同时，页面必须维持 Figma 定义的内容层级和主要构图，不得挤压截图、CTA 或故事轨道。
- 当用户连续、反向或快速点击故事按钮时，最终前景截图、标题、说明和选中态必须一致，不出现两张前景图或错误层级。
- 当截图资源加载缓慢或失败时，页面必须保留稳定舞台尺寸和可理解替代文本，不得让首屏布局塌陷。
- 当浏览器启用减少动态效果时，风带、环形位移、平滑滚动和非必要浮动必须停止，状态切换不得延迟或丢失。
- 当路线试查没有候选地点、选择无效、无结果、超时或失败时，页面必须在原工作区内提供明确状态和下一步，并保留仍有用的输入。
- 当路线数据只部分补齐时，页面必须展示可证明的信息；未知候车、步行或其他字段不得用猜测值补齐。
- 当下载资料尚未返回、结构无效或请求失败时，下载入口必须保持不可操作，不得回退到陈旧版本或显示原型二维码。
- 当用户从网站文案理解运营商支持时，页面必须区分“联营路线的跨运营商首程 ETA”与“完整跨运营商路线规划”。
- 当实现者寻找视觉基线时，必须能从本 feature 的 Figma 记录定位最终 Section、双端首屏、全部状态和动效说明，而不是依赖聊天记录或 Android 本地路径。
- 当页面继续向下滚动时，背景不得以深色波浪制造假结尾，也不得使用固定元素持续遮挡内容。

## 宪法对齐（必填）

- **产品来源**：Android 主项目当前 `README.md`、行程与查询工作流、跨运营商路线与站点映射、通知栏监控设计、本地化指南与 UI/UX 风格指南；本仓库当前页面、共享 UI 状态契约、下载 manifest、路线查询契约、获批 v1.3.1 截图 manifest 和 2026-08-21 视觉系统设计合同。产品事实只固定为网站内容，不把 Android 工程绝对路径、内部类名或调试信息暴露给网站用户。
- **产品范围**：升级公开首页的产品介绍、五故事首屏、路线试查、Android 下载、FAQ、联系和页尾，使网站清楚表达“香港巴士路线规划与导航 App”的价值。
- **排除范围**：不提供完整出行规划，不扩展到港铁、铁路、渡轮或其他非巴士交通；不新增 iOS 下载；不新增第四个营销屏、独立功能网格、证明条或使用场景卡；不改变 App 或服务端路线算法。
- **前后端边界**：本功能是纯前端视觉、内容与交互升级。前端消费既有路线试查、下载资料和内容契约；后端接口、错误格式、缓存和业务规则保持不变。前端不得依赖后端内部实现或 Android 工程运行时路径。
- **API 文档**：N/A。本功能不新增、修改或移除服务端 HTTP API，既有路线与下载 OpenAPI 3.1 契约保持权威且只做兼容性回归；若后续计划发现必须改变接口，应停止纯前端范围并另行立项。
- **服务端 DDD 边界**：N/A。本功能不修改服务端 bounded context、领域层、应用层、基础设施层或接口适配层。
- **服务端稳健性**：N/A。本功能不修改服务端 recovery、并发任务或日志；既有受控错误和脱敏响应作为前端降级输入，不得回退。
- **代码可读性**：后续实现需用简体中文注释解释环形舞台状态映射、动效降级、路线结果保留和下载三态等非显而易见边界；简单样式和值映射不添加重复代码字面含义的噪音注释。
- **三语范围**：覆盖 Header、五故事、路线试查全部状态、下载三态、安装说明、FAQ、联系、页尾、图片替代文本和辅助技术状态。`zh-Hant` 按香港交通与产品页面习惯独立审校，`zh-Hans` 使用自然简体，`en` 使用克制自然的英语产品表达；事实含义在三语之间保持一致。
- **UI 可视化**：获批视觉来源为 `docs/superpowers/specs/2026-08-21-homepage-visual-system-v131-design.md`、对应本地高保真原型证据及原生 Figma 设计。生产实现不得把整页视觉稿当作扁平图片。
- **Figma 设计**：使用 [BusIsComing Website — Homepage v1 Spec](https://www.figma.com/design/LAm6RjzFuFHsHFlcipx8pU/BusIsComing-Website---Homepage-v1-Spec) 中 [Homepage Visual System v1.3.1 — FINAL（`119:64`）](https://www.figma.com/design/LAm6RjzFuFHsHFlcipx8pU/BusIsComing-Website---Homepage-v1-Spec?node-id=119-64) 作为唯一获批视觉主入口；桌面首屏节点为 [`119:176`](https://www.figma.com/design/LAm6RjzFuFHsHFlcipx8pU/BusIsComing-Website---Homepage-v1-Spec?node-id=119-176)，手机首屏节点为 [`119:461`](https://www.figma.com/design/LAm6RjzFuFHsHFlcipx8pU/BusIsComing-Website---Homepage-v1-Spec?node-id=119-461)。版本、状态与验证范围见 [figma.md](./figma.md)。
- **双端适配**：桌面基准 `1440×960`，手机基准 `390×844`；补充验证 `320px`、常见 Android 真机宽度和三语长文案。手机使用独立构图，不是桌面缩放；关键不可漂移项由 Figma 与本规格共同约束。
- **外部集成与降级**：继续使用既有路线试查和下载资料来源。路线失败时保留输入并提供重试，不显示第三方原始错误或编造数据；下载资料非可用时不提供有效下载行动或二维码；截图资源来自受管、脱敏且 manifest 可追溯的生产素材。
- **验证与提交**：规格先通过需求质量清单、链接/路径、占位符、冲突标记和 `git diff --check` 验证，再只提交本 feature、`.specify/feature.json` 和必要的 feature 索引变更；不夹带无关工作区内容。

## 需求（必填）

### 固定内容合同

首屏繁体中文五个故事标题与说明为已确认内容，不得在实现阶段自行改写：

| 编号 | 标签 | 标题 | 说明 |
| --- | --- | --- | --- |
| 01 | 搜尋 | 隨心搜尋，出發更輕鬆 | 輸入起終點，即時比較合適路線 |
| 02 | 行程 | 常走的路，一按更省心 | 路線、車費與候車時間集中比較，選擇更清楚 |
| 03 | 沿途 | 一路看清，出行更安心 | 路線、轉乘與目前位置，沿途心中有數 |
| 04 | 班次 | 班次看得全，候車更從容 | 城巴、九巴與龍運到站時間集中呈現 |
| 05 | 出門 | 不用盯手機，出門更有把握 | 啟動一次，鎖屏持續更新候車與步行時間 |

`zh-Hans` 与 `en` 必须分别自然改写并独立审校，但不得扩大上述能力含义。

### 功能需求

- **FR-001**：系统必须把公开首页组织为 `HeroStory → RouteTrial → DownloadDecision → SupportEnding` 四段主结构，不得恢复独立功能网格、证明条、连续故事屏或第四个营销屏。
- **FR-002**：首屏必须同时提供品牌与完整导航、当前故事标题与说明、Android 下载、路线试查、当前 App 截图和五故事切换，并保持 Figma 定义的阅读优先级。
- **FR-003**：Header 在电脑和手机上都必须显示品牌、功能、常见问题、联系我们和语言入口；手机端不得删除核心入口或退化为含义不明的菜单。
- **FR-004**：首屏必须展示五个固定功能故事；切换故事时，标题、说明、主截图、故事选中态和辅助技术状态必须作为同一事务更新。
- **FR-005**：五张截图必须形成具有前后、远近、倾斜、清晰度和层级差异的环形舞台；前景图退后、目标图上前，不得退化为平面队列、简单淡入淡出或横向切入切出。
- **FR-006**：手机首屏必须完整显示前景手机的上下左右边框，故事按钮必须位于截图下方且不覆盖截图；不得显示灵动岛、硬件开孔、说明卡、“功能 01 / SEARCH”或证据标签。
- **FR-007**：桌面首屏可以保留 Figma 中已批准的低权重辅助信息，但不得新增会与标题、CTA 或主截图竞争的卡片或标签。
- **FR-008**：页面前三段必须使用浅绿与白色多层风带建立呼吸和远近感；背景不得包含紫色、霓虹、深色潮汐、固定底浪或改变文本对比度的动画。
- **FR-009**：持续风带的视觉周期必须处于约 `10–22` 秒的缓慢范围；手机环形主转场约 `880ms`，桌面主图转场约 `520ms`，并采用自然减速，不得闪烁或引发布局位移。
- **FR-010**：系统必须尊重减少动态效果偏好，关闭持续风带、环形大位移、平滑滚动和非必要浮动，同时保留静态远近层次、状态反馈和全部操作。
- **FR-011**：第二屏必须让用户完成既有香港巴士路线试查，并覆盖默认、地点候选、无效选择、加载、结果、空结果、失败、重试及保留结果状态。
- **FR-012**：路线结果卡必须优先展示路线号或组合、上下车摘要、预计候车、车费、“耗时 N 分钟”和“步行 N 米”。
- **FR-013**：路线卡不得为耗时和步行显示图标，不得显示“直达”或“转乘”标签，也不得显示服务无法证明的运营信息。
- **FR-014**：路线试查失败时必须保留仍有效的用户输入，显示本地化受控状态和单一下一步，不得暴露第三方原始错误或编造结果。
- **FR-015**：第三屏必须以“路线找到了，把它带在身边”的简洁叙事承接路线试查，并采用非卡片式、居中的紧凑下载行动；手机版使用适合窄屏的左对齐内容层级。
- **FR-016**：下载区不得展示“三步完成”、`BUILD 19`、“目前版本可下载”、`SHA 256`、虚假进度、安装完成承诺或大段下载自我解释。
- **FR-017**：Android 下载可用时，主按钮必须直接进入浏览器原生下载；版本、最低系统、大小和发布日期使用相同的小字号和权重，不得放大版本号或无意义拉满按钮。
- **FR-018**：桌面下载二维码必须由当前真实下载目标生成并与主按钮一致；手机端始终隐藏二维码；检查中和不可用状态不得显示二维码或有效下载链接。
- **FR-019**：下载行动必须使用已批准的克制“风带汇聚”提示，不得加入手指、放大镜、人物、插画或游戏化引导。
- **FR-020**：页面收尾必须由四项无卡片 FAQ、联系横条和浅色极简页尾组成，不得新增营销屏或深色结尾区域。
- **FR-021**：FAQ 必须默认展开安装问题，同一时间最多展开一项，并让展开状态、加减号、键盘、触控和辅助技术语义保持一致。
- **FR-022**：运营商相关文案必须把产品定位为巴士路线规划与导航 App，并准确区分“符合条件的联营路线可聚合城巴、九巴与龙运首程 ETA”与“当前并未提供完整九巴或龙运路线规划”。
- **FR-023**：用户可见页面不得展示 Android 工程本地路径、内部实现名称、调试信息或无法由当前源码、共享契约、下载资料证明的版本、大小、覆盖范围和隐私承诺。
- **FR-024**：所有新增或修改文案、图片替代文本和辅助状态必须覆盖 `zh-Hant`、`zh-Hans`、`en`，三语必须独立审校且功能覆盖一致。
- **FR-025**：切换语言时必须保留当前故事、滚动锚点、路线输入与结果、下载状态和 FAQ 展开状态。
- **FR-026**：所有主要触控目标必须至少为 `44×44 CSS px`；键盘焦点必须可见；装饰性后景截图不得进入焦点顺序或制造重复朗读。
- **FR-027**：系统必须在 `1440×960`、`390×844` 和 `320px` 宽度保持核心内容可见、无横向滚动、无重叠、无截图边框裁切，并适应三语标题长度。
- **FR-028**：生产页面必须使用获批、脱敏且 manifest 可追溯的 v1.3.1 真实 App 截图；不得在运行时读取 Android 工程路径，也不得把原型画面误标为真实 App 截图。
- **FR-029**：实现与视觉验收必须以 Figma 最终 Section `119:64` 为主视觉合同，并覆盖全部故事、路线状态、下载状态、FAQ 状态、双端布局和减少动态效果状态。
- **FR-030**：以下任一情况必须判定为视觉验收失败：标题换行偏离获批 Frame、主行动顺序或权重改变、手机边框裁切、故事按钮覆盖截图、后景退化为平面队列、导航入口缺失、新增未批准卡片/标签/图标/紫色色块/深色页尾，或 `390px` 出现横向滚动。
- **FR-031**：本功能必须保持既有路线与下载服务接口、错误格式、缓存策略和服务端行为兼容，不得以视觉升级为由扩大后端或 App 功能范围。

### 关键实体（涉及数据时填写）

- **首页故事**：由稳定编号、标签、三语标题、三语说明、主截图、替代文本和选中状态组成的五个产品价值单元。
- **截图舞台状态**：描述五张截图相对前景的环形位置、远近、可见度和当前活动项；视觉层级变化不改变故事内容身份。
- **路线试查状态**：用户起终点、地点选择、加载、成功结果、空结果、失败、重试及保留结果的可见状态集合。
- **路线摘要**：由路线号或组合、上下车摘要、候车、车费、耗时和步行组成的可比较结果；只承载服务能够证明的字段。
- **下载决策状态**：检查中、可用、不可用三态及当前安装包的公开版本资料；决定按钮、二维码和安装说明的可见性与可操作性。
- **支持内容**：四项 FAQ 的三语问题与答案、当前展开项、联系入口、隐私入口和返回顶部入口。
- **视觉合同**：Figma 最终 Section、关键节点、双端 Frame、交互状态、动效与不可漂移规则的可追溯集合。

- **SC-002**：五个故事在桌面和手机共 10 个基准状态中，标题、说明、前景截图和选中按钮 100% 对应；每次用户选择后 1 秒内达到稳定一致状态。
- **SC-003**：`1440×960` 与 `390×844` 的全部获批页面状态均不出现 FR-030 定义的视觉失败；`320px`、三种语言和常见 Android 真机宽度下水平溢出数量为 0。
- **SC-004**：在五故事完整循环和反向快速切换各 20 次的验收中，前景截图重复、错误标题、错误选中态和永久卡住的过渡次数均为 0。
- **SC-005**：路线试查的默认、候选、无效、加载、成功、空结果、失败、重试和保留结果状态均可独立触发并通过；失败状态中用户有效输入保留率为 100%，虚构路线或 ETA 数量为 0。
- **SC-006**：所有路线卡样本中，耗时与步行图标、“直达”及“转乘”标签的展示数量均为 0；服务能够提供的文字耗时与步行信息展示率为 100%。
- **SC-007**：在检查中、可用、不可用三类下载状态中，主按钮和二维码可操作性 100% 符合状态；桌面二维码与主按钮目标一致率为 100%，手机二维码展示数量为 0。

## 假设

- 视觉与交互决策已在前序讨论和 Figma `Homepage Visual System v1.3.1 — FINAL` 中完成，本规格无需重新选择视觉方向。
- 当前产品事实以 Android 主项目 `main` 的当前文档与源码为准；网站在构建时固定获批文案与素材，不在运行时读取 Android 项目。
- “巴士路线规划与导航 App”是品牌定位；当前完整路线规划能力仍以现有 App 和网站契约实际支持范围为准，联营 ETA 不自动扩大路线规划覆盖。
- 本功能是纯前端升级，现有路线与下载服务可以满足获批体验；若计划阶段发现必须改变服务端 HTTP API，应拆分为独立 feature，不在本范围内静默扩展。
- 当前 Android 下载仍由既有下载资料与稳定下载入口提供；版本、大小和发布日期均从当前权威资料展示，不在文案中硬编码易过期值。
- 当前公开版本只提供 Android 下载；iPhone FAQ 清楚说明尚未推出，不伪造 App Store 入口。
- 获批的五张 v1.3.1 核心功能截图可进入网站受管素材目录，并满足来源、脱敏、manifest 和替代文本要求。
- Figma 允许实现者读取最终 Section；若协作权限或工具额度暂时受限，仓库内设计合同和 Figma 导入源只作为定位与复核备份，不取代最终 Figma 视觉主入口。
