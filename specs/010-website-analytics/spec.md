**功能分支**：`feat/010-website-analytics`

**创建日期**：2026-07-21

## 用户场景与测试（必填）

### 用户故事 1 - 在不识别自然人的前提下统计访问（优先级：P1）

作为网站访问者，我希望主页浏览、路线试查和下载行为只以匿名浏览器标识进行统计，不记录 IP、查询内容或可用于指纹识别的原始网络信息，同时我的正常访问和下载不应因统计故障而失败。

**优先级原因**：隐私边界与业务可用性是统计功能可以上线的硬门禁，必须先于任何真实数据明细、Dashboard 集成或生产交付成立。

**独立测试**：分别以普通浏览器、无标识浏览器、篡改标识浏览器、已知机器人和统计存储不可用环境访问公开功能，验证匿名标识、事件记录、敏感字段排除、机器人过滤和业务降级行为。

**验收场景**：

1. **给定**普通浏览器首次访问主页，**当**APK 元数据请求到达服务端，**则**系统签发匿名浏览器标识并记录一次主页访问，但不保存 IP、完整 User-Agent、完整 Referrer 或 Cookie 原文。
2. **给定**同一浏览器继续试查路线和下载，**当**相关公开请求到达服务端，**则**事件关联到同一匿名浏览器标识，且标识不出现在路径、查询参数或业务请求体中。
3. **给定**统计存储暂时不可用，**当**用户访问主页、查询地点、查询路线或下载 APK，**则**公开功能维持原有成功或失败语义，统计故障不改变业务响应。
4. **给定**请求被识别为已知机器人流量，**当**请求到达可统计入口，**则**系统既不签发匿名访客标识，也不保存统计事件或专门机器人明细；宪章要求的通用请求日志仍可写入一条，但只能包含统一脱敏字段，不得包含 bot 标记、IP、User-Agent、Cookie 或其他身份线索。

### 用户故事 2 - 查看网站运营总览（优先级：P1）

作为网站维护者，我希望通过仅限私有访问的监控面板查看主页访问、路线试查和安装包下载的核心指标、趋势与转化情况，从而判断网站是否正常被使用以及用户在哪个环节流失。

**优先级原因**：可视化运营情况是本功能的直接业务价值，但只能在用户故事 1 的隐私采集硬门禁完成后接入真实数据。

**独立测试**：准备一组包含主页访问、地点查询、路线查询和下载请求的匿名事件，在 1440px 桌面与 390px 手机分别以 `zh-Hant`、`zh-Hans`、`en` 打开监控总览，确认语言默认值与持久化切换、指标卡、趋势图、两个漏斗、事件构成、下载版本和性能摘要均能按统一筛选条件正确展示且主要操作可达。

**验收场景**：

1. **给定**近 30 天存在多类匿名事件，**当**维护者打开监控总览，**则**页面展示 PV、UV、成功试查、下载请求、成功率、趋势、事件构成和漏斗等核心信息。
2. **给定**维护者选择语言、设备、来源、结果、平台或版本筛选，**当**筛选生效，**则**所有受影响的指标和图表使用同一筛选范围，并能与上一等长周期比较。
3. **给定**监控总览保持打开，**当**距上次成功载入达到 60 秒，**则**总览自动获取最新结果并显示最近更新时间。
4. **给定**维护者分别使用 1440px 桌面和 390px 手机，**当**其查看总览和操作筛选器，**则**相同核心指标、趋势、漏斗、状态和筛选语义均可读可达，只允许布局随 viewport 重组。
5. **给定**维护者首次进入或切换监控语言，**当**浏览器语言受支持、仅提供通用中文或已有持久化选择，**则**US2 首次实现的 i18n provider 分别使用精确语言、`zh-Hant` fallback 或持久化值；切换后当前 hash、筛选和时间范围保持不变。

### 用户故事 3 - 调查事件、访客路径和异常（优先级：P2）

作为网站维护者，我希望从总览进入匿名事件明细、匿名访客时间线、失败与性能以及系统状态页面，从而定位转化变化、请求失败或统计写入问题，而不接触被禁止的个人或查询内容。

**优先级原因**：总览回答“发生了什么”，明细和诊断页面回答“由哪些匿名事件构成”，是持续运营和排障所需的第二层能力。

**独立测试**：使用包含多会话、多结果、多语言、多设备和失败事件的数据集，在 1440px 桌面与 390px 手机以三种语言验证六个详细工作区的文案与格式化、分页、访客搜索、30 分钟会话切分、失败分类、响应时间分位值、系统状态和主要调查操作。

**验收场景**：

1. **给定**维护者查看事件明细，**当**其筛选事件类型、结果、语言、设备、来源、平台或版本，**则**系统返回分页结果并只展示允许的脱敏字段。
2. **给定**维护者输入完整匿名访客标识，**当**其打开访客详情，**则**页面展示首次/最后出现时间、事件计数、会话计数和按时间排序的事件时间线，列表默认只显示截断标识。
3. **给定**同一访客连续产生事件后超过 30 分钟没有活动，**当**再次产生事件，**则**时间线将后续事件划分为新的派生会话。
4. **给定**存在业务失败或统计写入丢弃，**当**维护者查看失败与性能或系统状态，**则**能看到脱敏失败分类、响应时间、数据库状态、最后成功写入时间和进程启动以来的丢弃数量。
5. **给定**维护者使用 390px 手机调查事件或访客，**当**表格转为卡片、筛选器收纳或时间线纵向展示，**则**筛选、分页、精确访客检索、复制反馈和刷新操作保持可用。

### 用户故事 4 - 查看 APK 信息并可靠下载（优先级：P2）

作为主页访问者，我希望在 Android 下载入口看到当前 APK 的版本和大小，以便确认下载内容；即使版本信息暂时获取失败，我仍能继续下载安装包。

**优先级原因**：清楚展示包信息能提升下载信任，同时必须避免辅助元数据成为下载可用性的单点故障。

**独立测试**：分别模拟元数据成功、元数据失败、安装包可用和安装包不可用，在桌面与 390px 手机验证主页文案、下载入口、响应式展示和访问统计口径。

**验收场景**：

1. **给定**当前 Android APK 元数据可用，**当**用户打开主页，**则**下载入口展示当前版本和以当前语言格式化的安装包大小。
2. **给定**元数据请求失败，**当**主页完成降级展示，**则**版本与大小显示为暂时不可用，不显示硬编码旧值、不提供手动重新载入按钮，且下载入口仍可点击。
3. **给定**用户发起 APK 下载，**当**下载请求成功或失败，**则**系统记录请求时间、匿名访客、结果、耗时、服务端推导的平台，以及成功响应对应的实际包版本。
4. **给定**用户在桌面或手机主页查看下载入口，**当**版本信息成功或降级展示，**则**版本、大小、不可用状态和下载按钮都不重叠、不裁切且可操作。

### 用户故事 5 - 验证监控页面的双端三语一致性（优先级：P3）

作为维护者，我希望在电脑上使用高密度 Dashboard，在手机上快速查看关键指标和系统健康状态，并能切换繁体中文、简体中文和英文。

**优先级原因**：每个涉及 UI 的用户故事都必须同步实现桌面和手机形态；本故事只承担跨七个工作区的三语、双端、可访问性和视觉一致性发布回归，不是事后补做移动布局。

**独立测试**：在 1440px 桌面和 390px 手机 viewport 下，以 `zh-Hant`、`zh-Hans`、`en` 分别检查核心页面、主要操作和所有加载/空数据/错误状态。

**验收场景**：

1. **给定**维护者使用桌面浏览器，**当**其浏览总览和专题页面，**则**侧栏、筛选器、图表和表格均完整可用，无关键内容重叠或不可见。
2. **给定**维护者使用手机浏览器，**当**其打开移动端总览，**则**关键指标、趋势、漏斗、下载和系统健康以纵向优先级展示，主要导航可触达。
3. **给定**维护者切换语言，**当**页面重新展示，**则**筛选范围和当前页面保持不变，`zh-Hant` 符合香港产品语境，英文自然克制。

### 边界情况

- 当浏览器没有匿名标识、标识已过期或签名无效时，系统签发新的不可预测标识；无效值不得继续用于关联事件。
- 当浏览器清除 Cookie、切换浏览器或设备时，系统将其视为新的匿名访客；UV 不声称等同于真实自然人数。
- 当请求声明 DNT 或 GPC 时，匿名统计仍按已确定策略启用，页面不提供退出控制；隐私说明必须清楚披露此行为。
- 当请求属于已知机器人时，机器人判断只在请求处理期间使用，不签发 Cookie、不保存统计事件、不写 bot 标记或专门机器人明细；仍允许与普通请求相同的一条通用脱敏请求日志，以满足 HTTP 入口可观测性。
- 当主页 HTML 被打开但元数据请求没有到达服务端时，不计入 PV；只统计 `/zh-hant/`、`/zh-hans/`、`/en/` 三个主页，不统计隐私政策页。
- 当元数据读取失败但请求已到达服务端时，仍记录主页访问；元数据失败不得阻断稳定下载入口。
- 当地点输入触发多次 300ms 防抖请求时，每次到达服务端的请求都保留原始事件，但漏斗按成功独立访客去重，避免输入过程夸大转化。
- 当用户只直接下载、没有在同一派生会话访问主页时，下载进入下载总量，但不算完整“主页 → 下载”漏斗转化。
- 当路线查询成功但 ETA 查询发生时，不新增 ETA 统计事件；本功能仅统计地点查询和路线查询。
- 当下载失败且无法确定包版本时，版本可以为空；不得用当前配置版本冒充实际成功返回版本。
- 当语言、设备或来源无法可靠归类时，使用 `unknown` 或 `other` 粗粒度分类，不保留用于再次识别用户的原始值。
- 当监控数据库不可读时，Dashboard 展示明确不可用状态；公开主页、试查和下载继续运行。
- 当时间范围内没有数据或筛选无匹配时，分别展示“无数据”和“无筛选结果”，不把二者混为系统错误。
- 当明细长期增长到 100 万行时，常用 Dashboard 查询和访客时间线仍应满足本规格性能目标；系统不自动删除或备份明细。
- 当私有监控入口被从公网直接访问时，请求必须无法到达监控页面或监控数据接口。
- 当用户在手机和电脑之间切换访问时，指标定义和筛选语义保持一致，但布局按设备重新组织。
- 当前端 UI 继续迭代时，后续阶段从 [figma.md](./figma.md) 定位权威文件、导入锚点、关键画板和状态；不得把设计稿中的静态示例数值当作运行时产品事实。
- 当服务端内部错误、panic 或自建并发任务异常发生时，HTTP 入口执行恢复并记录脱敏上下文，不得使整个服务因无保护异常退出。

## 需求（必填）

### 功能需求

#### APK 元数据与主页展示

- **FR-001**：系统必须向主页提供当前 Android APK 的平台、可用状态、版本名称、版本代码、文件名、字节大小、最后更新时间和稳定下载地址，不暴露内部文件路径或源路径。
- **FR-002**：主页必须在 `zh-Hant`、`zh-Hans`、`en` 中展示当前版本与本地化安装包大小；大小由字节值格式化，不从静态文案读取。
- **FR-003**：当元数据不可用时，主页必须显示版本与大小暂时不可用，不显示硬编码旧值、不提供手动重新载入按钮，并保持稳定下载入口可用。
- **FR-004**：元数据响应不得被用于长期缓存陈旧的当前版本或不可用状态。

#### 匿名访客与隐私边界

- **FR-005**：系统必须使用服务器签发的不可预测匿名浏览器标识区分 UV；标识需具备完整性保护，默认有效期一年，并由浏览器通过仅限 HTTP、仅限安全连接、同站点宽松、主机限定、根路径 Cookie 自动携带。
- **FR-006**：匿名访客标识不得作为业务路径、查询参数或请求体字段传递；任何可统计公开入口均可在普通非机器人请求中签发或轮换标识。
- **FR-007**：UV 必须定义为持有同一有效匿名标识的独立浏览器；系统不得把该值表述为自然人数或跨设备用户数。
- **FR-008**：匿名统计始终启用，不提供退出控制；DNT 或 GPC 不改变已确定的统计行为，隐私政策必须披露标识、有效期、用途和长期保留规则。
- **FR-009**：系统不得在统计明细、聚合结果或应用日志中保存 IP、完整 User-Agent、完整 Referrer、完整 Cookie、查询词、起终点、坐标、请求体、token、第三方原始响应或其他超出本规格的指纹参数。
- **FR-010**：系统必须在 Cookie 验证/签发和统计写入前排除已知机器人；被排除请求不得签发匿名标识、保存统计事件或写专门机器人明细日志。统一 HTTP request logger 可以记录一条与普通请求相同的通用脱敏日志，但不得记录 bot 标记、IP、User-Agent、Cookie 或其他身份线索。
- **FR-011**：系统只可从请求期间使用的原始信息推导并保存 `zh-Hant`/`zh-Hans`/`en`、`desktop`/`mobile`/`tablet`/`other`、`direct`/`search`/`referral`/`internal`/`unknown` 等粗粒度分类。

#### 事件记录与统计口径

- **FR-012**：系统必须支持且仅在本功能范围内记录 `page_view`、`place_query`、`route_query`、`download_request` 四类事件；ETA 查询不记录为独立事件。
- **FR-013**：`page_view` 只在 `/zh-hant/`、`/zh-hans/`、`/en/` 主页触发的 APK 元数据请求到达服务端时记录；隐私政策页和仅返回 HTML、未到达元数据请求的访问不计入。
- **FR-014**：地点查询和路线查询每次到达服务端都必须分别记录，不能合并或把地点查询误记为路线查询。
- **FR-015**：每个允许记录的事件必须包含发生时间、匿名访客标识、事件类型、结果、状态类别、耗时和允许的粗粒度分类；成功和失败请求都要记录。
- **FR-016**：系统不得在统计事件中保存地点查询输入、路线起终点、坐标、ETA token 或第三方响应内容。
- **FR-017**：下载事件必须记录服务端从下载路由推导的平台；成功响应记录实际返回的版本名称、版本代码和包大小，失败时版本允许为空；平台枚举必须允许未来增加 iOS，但当前正式范围仅 Android。
- **FR-018**：下载指标必须表述为下载请求或成功响应，不得表述为安装完成。
- **FR-019**：系统必须按同一匿名访客的事件时间顺序，以连续 30 分钟无活动作为边界派生会话；派生会话不作为独立采集数据源。
- **FR-020**：系统必须保留地点输入过程中每次到达服务端的原始请求事件，同时在漏斗中以成功独立访客去重。
- **FR-021**：系统必须分别计算“主页 → 成功地点查询 → 成功路线查询”和“主页 → 成功下载响应”两个漏斗；只有同一派生会话内按时间顺序发生的成功行为才进入对应完整漏斗。

#### 数据保留与故障降级

- **FR-022**：系统必须长期保存允许范围内的事件明细，不预先保存 Dashboard 汇总结果，不提供自动删除、生命周期清理或备份功能。
- **FR-023**：统计查询必须从明细按请求时的时间范围和筛选条件计算；统计口径不能依赖浏览器自行汇总。
- **FR-024**：统计写入必须使用 `ANALYTICS_WRITE_TIMEOUT_MS` 配置的独立 deadline，默认 `50ms`，合法闭区间为 `10–200ms`；每条允许事件只同步尝试一次。超时或失败只记录脱敏类别并把 `droppedSinceStart` 增加一次，不重试、不改变公开业务响应。配置缺失使用默认值；非整数或越界时 analytics 初始化降级为 no-op，公开服务仍须启动，私有 system 状态只暴露受控原因类别。
- **FR-025**：统计存储必须通过可替换的存储边界访问，使未来更换明细存储时不改变事件和 Dashboard 业务语义。

#### 私有监控 Dashboard

- **FR-026**：监控页面和监控数据接口必须只允许通过服务器本机私有入口访问，不得由公开网站反向代理或公网路由暴露；运维文档必须说明 SSH 隧道访问方式。
- **FR-027**：监控 Dashboard 必须提供总览、流量与试查、下载分析、事件明细、匿名访客、失败与性能、系统状态七个主要工作区。
- **FR-028**：总览默认展示近 30 天，支持小时、日、周、月和自定义时间范围，并支持与上一等长周期比较。
- **FR-029**：Dashboard 必须支持语言、设备、来源、结果、平台和版本筛选；所有指标、图表和表格必须明确当前筛选范围与更新时间。
- **FR-030**：总览必须至少包含 PV、UV、人均访问、成功路线试查、下载请求、请求成功率指标卡，PV/UV 趋势、两个转化漏斗、事件构成、响应时间分位值和下载版本/平台分布。
- **FR-031**：事件明细必须分页展示，默认截断匿名访客标识，并允许用完整标识精确检索；不得提供导出、删除、编辑或一次性下载全部历史明细能力。
- **FR-032**：匿名访客页必须展示完整标识搜索/复制、首次和最后出现时间、事件/会话计数、常见粗粒度分类以及按时间排序的会话时间线。
- **FR-033**：失败与性能页必须提供成功率、脱敏失败分类以及各公开统计入口的请求量、P50 和 P95；系统状态页必须提供数据库状态、最后成功写入、进程内丢弃数量和私有入口状态。
- **FR-034**：总览必须每 60 秒自动刷新；事件明细、访客、失败与性能等详细页面不得自动刷新，以避免调查过程中的结果跳动。
- **FR-035**：Dashboard 必须区分加载、时间范围无数据、筛选无结果、普通查询失败和监控数据库不可用状态，并明确数据库不可用不影响公开业务。
- **FR-036**：Dashboard 和主页新增文案必须支持 `zh-Hant`、`zh-Hans`、`en`；每个涉及 UI 的用户故事必须在自身完成条件内同时实现并验证电脑与手机形态，不能把移动布局延后到单独收尾阶段。

#### 契约、稳健性与可追溯性

- **FR-037**：公开下载/元数据、地点/路线查询和私有监控 HTTP 能力必须分别维护 feature-scoped OpenAPI 3.1 YAML 权威契约；三份 feature YAML 只在实现阶段单向同步到 shared，私有监控契约不得导致私有接口注册到公开路由。
- **FR-038**：HTTP 入口必须具备异常恢复和不含受禁信息的结构化请求日志；不得以 `panic` 表达业务失败，自建并发任务必须捕获异常并记录脱敏上下文。
- **FR-039**：复杂隐私、统计口径、会话、漏斗、下载归因、分类和降级规则必须通过清晰命名、聚焦函数与必要的中文注释保持可审查性。
- **FR-040**：后续计划、任务和实现必须能从本规格打开 [figma.md](./figma.md) 并定位权威 Figma 文件、导入锚点、关键画板、交互状态和版本说明。

### 关键实体（涉及数据时填写）

- **匿名访客**：代表持有同一有效服务器签发标识的浏览器；包含不可预测标识、首次和最后出现时间等关联语义，不代表自然人。
- **匿名事件**：一次允许记录的主页访问、地点查询、路线查询或下载请求；包含时间、类型、结果、耗时、匿名访客关联和粗粒度分类，不包含受禁原始信息。
- **事件结果**：描述请求是否成功、可用于统计的状态类别以及失败分类；不保存第三方原始响应。
- **下载归因**：下载事件的服务端推导平台与实际响应版本信息；成功时完整，失败时版本可空。
- **派生会话**：同一匿名访客按 30 分钟无活动边界从明细临时推导出的有序事件集合，用于访客时间线和漏斗。
- **Dashboard 查询**：维护者选择的时间范围、粒度、比较周期和分类筛选条件，以及从明细计算的指标、序列、分布、漏斗或分页结果。
- **APK 元数据**：当前可下载包的平台、状态、版本、文件名、字节大小、更新时间和稳定下载地址；是主页展示与成功下载归因的事实来源。
- **系统健康快照**：监控存储可用性、最后成功写入、进程内丢弃数量和私有入口状态的当前观察结果。

## 成功标准（必填）

### 可衡量结果

- **SC-001**：在包含四类事件、成功/失败结果和多语言/设备/来源的验收数据集中，PV、UV、事件计数、两个漏斗和上一周期比较结果全部与人工计算一致。
- **SC-002**：对数据库和应用日志进行自动检查时，IP、完整 Cookie、完整 User-Agent、完整 Referrer、查询词、地点、坐标、请求体、token 和第三方原始响应的出现次数均为 0。
- **SC-003**：已知机器人测试请求产生的匿名访客 Cookie、统计事件和专门机器人明细日志均为 0 条；允许的通用请求日志只包含统一脱敏字段且不含 bot 标记或身份线索。普通首次访问能获得有效匿名标识并在后续请求中稳定复用。
- **SC-004**：在统计存储完全不可用的测试中，主页元数据、地点查询、路线查询和 APK 下载的业务响应与统计正常时保持相同语义，统计故障导致的额外业务失败为 0。
- **SC-005**：在元数据请求失败但 APK 可下载的测试中，100% 的主页展示为“版本与大小暂时不可用”，且下载入口仍能完成下载请求。
- **SC-006**：在不超过 100 万条明细的目标规模下，常用 Dashboard 查询和单个访客时间线的服务端结果在 1 秒内返回。
- **SC-007**：监控页面和监控数据接口通过公网网站地址访问的成功次数为 0；维护者通过文档化 SSH 隧道能够完成访问。
- **SC-008**：总览在保持打开时每 60 秒刷新一次；详细调查页面在用户未主动刷新时结果不会自动跳动。
- **SC-009**：在 1440px 桌面、390px 手机和 `zh-Hant`、`zh-Hans`、`en` 组合下，所有核心指标和主要操作均可读可达，关键内容重叠、裁切或不可见问题为 0。
- **SC-010**：维护者能在 2 分钟内从总览定位到指定失败事件或匿名访客时间线，并能看到所需脱敏上下文而不接触受禁数据。
- **SC-011**：后续实现者能从本规格在 1 分钟内打开三份 feature 权威 OpenAPI 路径、Figma 既有导入锚点和 v1.1 补充导入说明，并找到对应接口范围、13 张关键画板和状态说明。
- **SC-012**：隐私政策明确说明匿名标识、1 年有效期、统计始终启用、UV 含义、数据长期保留和不记录 IP；三语审校中不存在改变这些事实的翻译差异。

## 假设

- 日均匿名事件不超过 1,000 条，长期明细不超过 1,000,000 条。
- 匿名统计数据允许丢失，只保留一份，不要求备份、恢复点或删除功能。
- 主页前端在正常打开时会请求 APK 元数据；只有请求真正到达服务端才计入主页 PV。
- 当前正式安装包宿主平台只有 Android，iOS 仅作为事件与筛选枚举的未来扩展位。
- 版本和大小是动态事实；Figma 与测试样例中的静态数值只用于展示结构，不能成为运行时回退值。
- 网站访问者无需登录；维护者通过服务器 SSH 权限和本机私有监听边界访问 Dashboard，不在本功能中新增公网登录系统。
- 所有汇总、比较、漏斗和会话均在监控查询时从明细计算，不建立预计算统计事实。
- 浏览器禁用或清除 Cookie 会降低同一浏览器 UV 的连续性，这是匿名且不采用指纹识别方案的已接受限制。
- 来源和设备分类只追求运营级粗粒度准确性，无法归类时允许使用 `unknown` 或 `other`。
- `backend/downloads/android/current.json` 与实际成功返回包共同决定当前包事实；内部路径、校验来源和签名信息不向主页元数据展示。
